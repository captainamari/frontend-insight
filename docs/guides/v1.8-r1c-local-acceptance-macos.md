## 1. 版本与环境

Apple Silicon Mac、Docker Desktop原生arm64且Compose v2可用；Node.js≥24、仓库锁定pnpm版本。先保存本地改动：

```bash
git fetch origin
git switch agent/v1-8-r1c-score-management
git pull --ff-only origin agent/v1-8-r1c-score-management
git rev-parse HEAD
git log -1 --oneline
pnpm install --frozen-lockfile
pnpm check
pnpm test:r1c
pnpm test:r1a
pnpm test:r1b
```

记录HEAD，并与Actions的head_sha及checkout步骤比对。基线为`1ad54dff106af1403adbce107e802d0aa56592d9`；不要比较到main。

## 2. 保留现有测试数据启动

```bash
./scripts/dev bootstrap
./scripts/dev up
./scripts/dev status
```

默认不要求reset。本次没有schema修改。如果你的测试库与现有refactor基线兼容，可直接更新启动。

`smoke`和verifier会写入测试事件或测试配置；建议在专用本地验收环境执行，不指向生产服务。

```bash
./scripts/dev smoke
./scripts/dev verify-r1a
./scripts/dev verify-r1b
./scripts/dev verify-r1c
```

`verify-r1c`复用现有verifier容器连接真实MySQL/API。预期输出`status:passed`、`milestone:R1-C foundation only`；验证运营/质量两类真实版本的配置校验、缺目标/owner/partial提示、admin/viewer、拒绝注入facts，以及预检不改变版本/分数/审计数量。该输出不表示真实分数或完整UI已经交付。

## 6. 排错

| 现象                             | 检查                                                     |
| -------------------------------- | -------------------------------------------------------- |
| Docker命令不存在或engine未运行   | 启动Docker Desktop；检查原生arm64和Compose v2            |
| 端口占用                         | 3000/3200/4173/4174；检查.env.m5配置，不清库解决端口问题 |
| 登录失败                         | 确认ASCII密码及seed成功；查看`./scripts/dev logs api`    |
| 未知verify-r1c命令/404预检       | 核对分支SHA；重新build/up，不只更新前端                  |
| preflight valid:true但value:null | 正常；这是未保存配置的校验，不是事实查询或数值预览       |
| partial/not_collected            | 缺规范事实/查询；保持真实状态，不修改目录标签或补0       |
| 质量模板不能激活                 | 参数方案已批准，仍需指定owner并实现正式模板/产品流程     |
| 样本/目标不足                    | 修正业务配置或等待真实样本，不从测试fixture填入生产数据  |

结束时执行`./scripts/dev down`保留数据。详细剩余工作见 [进度报告](../progress/v1.8-r1c-results.md) 和 [评审决策](../progress/v1.8-r1c-decisions.md)。
