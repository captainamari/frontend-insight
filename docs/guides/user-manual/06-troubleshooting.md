# 06 · 排障、限制与问题交接

[返回目录](README.md) · 前一篇：[设置与接入](05-settings.md)

先保留当前链接和界面状态，再改变条件。普通使用者可检查项目、环境、时间、筛选与权限；需要查接收、消费和存储时交维护者，避免用重置数据库解决查询问题。

## 先按这个顺序排除

1. **是不是同一项目？** 核对业务应用 `appId` 与平台项目，不只比较展示名称。
2. **是不是同一环境？** SDK 的 `env` 与平台选择一致；`dev` 数据不会出现在 `staging/prod`。
3. **事件是否在窗口内？** 读具体起止值，结束不含；核对项目时区与本地时钟。
4. **是否被其他筛选排除？** 页面路径、错误类别、错误组、模式、模块、版本和分页都有影响。
5. **事件是否已经可查询？** 接收成功不等于异步入库；看请求 ID、测试回执及链路状态。
6. **结果是空还是失败？** 无数据、样本不足、未采集、预算超限、权限不足和 API 失败采取不同动作。

## 场景实验室触发 JS 错误后看不到数据

这是 R8 验收反馈中特别修复过的场景。修复前，质量分析刷新只重查旧 `from/to`，新错误可能发生在旧结束时间之后；切环境仍沿用旧窗口，所以也看不到。演示说明曾误写 production，实际 SDK 发送 `dev`。

在**已部署该修复**的环境中按以下操作：

1. 打开场景实验室，记下显示的实际 `appId`、`dev` 和 release。默认演示项目通常是 M5 Demo，但以页面显示的 appId 和实际项目映射为准。
2. 在平台打开该项目 → “页面分析” → “质量分析”。选择 `dev`、“最近 7 天”、“全部页面”、“全部类别”；若已进入某错误组，点“返回全部错误组”。
3. 在实验室点击“模拟 JS 异常”，记下触发时间。
4. 返回质量分析，点击**页面里的“刷新”按钮**；确认顶部结束时间已推进到触发之后。等待消费后仍未出现，可再次点击该按钮。
5. 核对错误实例的路径、时间和 release。切到 staging 或 prod，不应出现这条 dev 事件；隔离本来就是预期行为。

使用自定义历史区间时，刷新不会扩大日期，需手动修改结束时间。浏览器 F5 和复制旧链接保留时间快照，不能代替质量页“刷新”。一条错误能出现在实例表不代表已经达到质量分数样本门槛；没有激活质量分数版本也不妨碍错误实例查询。

若仍失败，维护者需检查实际部署是否包含 `4948ece`，再按 appId、env、时间和请求／事件 ID 定位接收与消费链路。现有修复记录包含自动化证据，**修复后手工复验仍待确认，不能据此宣称最终验收通过**。详见 [原始反馈与修复记录](../../progress/v1.8-r8-quality-refresh-fix.md)。

## 常见问题表

| 现象                         | 优先检查                                               | 用户动作／维护者交接                                                             |
| ---------------------------- | ------------------------------------------------------ | -------------------------------------------------------------------------------- |
| 登录失败                     | 账号、密码、部署地址及服务可用性                       | 联系维护者处理账户，不从旧验收文档猜生产密码                                     |
| 登录后没有项目               | 搜索条件与项目访问权限                                 | 清空搜索；提供账号与目标项目给管理员                                             |
| 打开分享链接是无权限         | 当前登录身份与项目授权                                 | 分享地址不授予权限；由管理员核对成员                                             |
| 看得到但无法编辑             | 全局角色、项目返回权限、版本是否草稿                   | viewer 只读；active 不可原地改，按草稿流程修改                                   |
| 新项目没有分数               | 初始模板是草稿，业务确认及事实门槛未满足               | 确认并激活对应类型，读取缺失项，不填演示数字                                     |
| 有错误实例但质量分数空白     | 分母、性能样本、质量版本和来源覆盖                     | 分别检查实例采集与评分门槛；两者不是一回事                                       |
| 改了质量指标，版本库像没变化 | 类型筛选、是否保存草稿、激活状态                       | 选“质量”或“全部类型”，核对新版本 ID                                              |
| 保存配置后概览没变化         | 保存的是草稿，展示绑定或版本尚未激活                   | 查看 diff／影响，完成评审激活，再核对消费页版本                                  |
| 同名指标两页数字不同         | 项目／模块／页面范围、时间、环境、版本、观察值／正式值 | 先统一上下文；不要立即判计算错误                                                 |
| 刷新后仍显示旧结果           | stale 提示、加载失败或链接固定窗口                     | 看错误、重试并核对版本；新错误按上面的专门流程                                   |
| 错误表翻页失败               | 一小时分页快照过期或筛选已变                           | 回到第一页；不是删除数据                                                         |
| 查询预算超限                 | 范围过大或事件密度太高                                 | 优先缩短时间；页面筛选辅助定位，但质量查询不保证因此减少扫描量；保留提示交维护者 |
| 页面时长为 `—`               | 缺少或无效 `page_leave`                                | 看有效样本及 coverage；开发者检查离开／可见时长接入                              |
| 页面访问有数据，任务没有     | 页面 operation 绑定、工作流激活及真实实例上报          | 与开发者确认显式关联；模块内有工作流并不足够                                     |
| 组织维度为空                 | 目录、接入声明、生效窗口、桶闭合及小组人数             | 查看实际原因；当前 k=5 整族隐藏不是查询故障                                      |
| 测试事件 accepted 后待证实   | 异步消费尚未完成或链路失败                             | 保留 request ID，请维护者检查队列、consumer、存储                                |
| 接入被 Origin 拒绝           | 协议、域名、端口是否精确匹配                           | 由管理员核对白名单与业务真实来源                                                 |
| 旧 SDK 事件被 blocked        | 探针版本策略                                           | 按接入方升级计划处理；策略删除不等于业务自动升级                                 |
| 外部接口返回拒绝             | 凭证、启用状态、env、范围、过期、限流                  | 保存安全 code/requestId；按实际原因修正                                          |
| 刷新后找不到导出凭证         | 明文只显示一次                                         | 无法读回，管理员轮换并更新消费方                                                 |
| 异常访问无法启用             | 规则尚未真实批准                                       | 完成真实评审并登记，不能使用测试批准记录                                         |

## 哪些结论目前不能从系统直接得出

- 无记录不能证明无错误、无人访问或无人完成任务；只能描述已观测范围。
- API 技术成功不能代替业务成功，超时不能代替明确失败。
- 可见时长、跳出率和重复操作不能直接成为个人绩效判断。
- 组织目录、接入声明和兼容 SDK 观测各自提供不同证据，任何一个都不单独证明所有客户端完全无丢失。
- 错误抽屉不是视频回放或完整请求日志；缺少原始输入、payload、header、body、DOM 等内容符合当前产品边界。
- 没有事实的多 IP、权限拦截等能力保持不可计算；不要把需求文档中的未来目标当当前数据。
- 可查询数据受实际保留范围约束；修改保留设置或指标定义不能恢复已经不在存储中的历史事件。

## 提交问题时附上什么

把下面内容填在工单或消息中，无需提供密码、访问令牌或原始业务身份资料：

```text
问题标题：
发生时间及时区：
平台部署版本／提交（不知道可写未知）：
项目名称／项目 ID／业务 appId：
环境：dev / staging / prod
当前页面链接：
查询范围：from = ...；to = ...（结束不含）
登录角色（无需密码）：
实际筛选：模块／页面／类别／错误组／实例模式／分页
指标或分数版本：
重现步骤：1. ... 2. ... 3. ...
期望结果：
实际结果与提示：
错误组 ID／发生时间／请求 ID（如有）：
截图：包括项目、环境、范围和提示；隐藏凭证
已尝试：刷新／回到第一页／清空筛选／缩小范围等
```

维护者接手后可从 [开发者学习文档](../../learning/README.md)、[R8 反馈修复](../../progress/v1.8-r8-quality-refresh-fix.md)、[生产部署说明](../production-ubuntu-22.04.md) 继续定位。排障结果应区分“原因已定位”“代码已修复”“自动化已验证”“用户已复验”，不要合并成一个未经核实的“完成”。
