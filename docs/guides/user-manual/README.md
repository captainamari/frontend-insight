# Frontend Insight 用户操作指南

这套指南面向平台使用者：第一次登录的人可以按任务快速上手；负责人、运营、测试与管理员可以继续学习数据口径、配置和排障。开发维护者请转到 [开发者学习文档](../../learning/README.md)。

**适用基线：** `agent/v1-8-r8-cleanup-acceptance` 的 `641e106`，包含 `4948ece` 质量分析刷新修复；核对日期为 2026-10-09。本文按实际界面和实现编写，不将需求中的计划视为已上线。部署版本不同，界面可能不同；本指南也不代表最终验收通过，阶段状态以 [R8 结果](../../progress/v1.8-r8-results.md) 为准。

产品内有“全部项目”入口，以及项目内的五个模块：**项目概览、业务分析、页面分析、指标管理、设置**。不要将演示应用的“场景实验室”当作平台里的第六个项目模块；它是用于产生测试行为的独立应用。

## 推荐阅读路线

- 业务负责人：01 → 02 → 04 的“分数如何读”；每天看状态、原因和变化，每周检查任务结果与实际业务目标。
- 产品／运营：01 → 02 → 03 的“运营分析”；提出需要调整的页面归类、核心页面和使用目标，交管理员配置。
- 测试／问题处理人：01 → 03 的“质量分析” → 06；从项目、环境、错误组、发布版本和实例建立问题单。
- 项目管理员／接入开发者：01 → 05 → 04 → 06；先证明采集可查询，再配置业务定义、版本和解释。

这些是工作职责，不是系统新增的账号角色。权限仍由实际账号与项目授权决定，见 [权限表](01-getting-started.md#账号角色与业务职责)。

## 阅读数据前的三个约定

1. **“没有记录”不等于“没有问题”。** 数据可能尚未接入、尚未入库、样本不足或被筛选排除。
2. **同口径才能比较。** 项目、环境、时间、时区、指标版本、有效样本与覆盖状态都影响结果。
3. **先解释后下结论。** 原始观察、正式指标和评分是不同层级；页面上的缺失原因是分析的一部分。

本文中的项目名、工作流和路由示例仅用于说明操作，不会自动在你的系统里创建。正式地址、账号、项目以及业务目标由维护者或项目负责人提供。
