# v1.8 R1-A 本地手工验收指引（Apple Silicon Mac）

> 适用分支：`agent/v1-8-r1a-analysis-objects`<br>
> 产品基线：`docs/product/requirements-v1.8.md`<br>
> 开发基线：`docs/planning/mvp-plan-v1.5.md` R1-A

R1-A 只验收“指标管理 → 分析对象”：功能模块、页面定义和工作流定义。运营/质量指标公式与版本属于 R1-B/R1-C，工作流事实与漏斗属于 R4-B，本阶段看到“尚未接入”是正确状态，不能用 `0` 代替。

## 1. 验收前准备

- Apple Silicon Mac，Docker Desktop 与 Compose v2 已启动；
- Node.js 24、pnpm 11.15.1；
- 当前分支为 `agent/v1-8-r1a-analysis-objects`；
- R0 数据仍是可丢弃测试数据。执行 reset 会删除且只删除 `frontend-insight-m5` Compose 项目的 named volumes。

先执行静态和专项验证：

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm test:r1a
bash -n scripts/dev
```

预期：格式、workspace、contract、规范名扫描、lint、类型、单元测试和构建全部通过；R1-A 专项覆盖 route 归一化、步骤/终态约束、普通 class 脆弱性提示、viewer 403 和数据库基线结构。

## 2. 从空库启动并运行集成验证

确认本地数据可删除后执行：

```bash
./scripts/dev reset --confirm-local-data-loss
./scripts/dev bootstrap
./scripts/dev up
./scripts/dev smoke
./scripts/dev verify-r1a
```

预期 `verify-r1a` 最后一行包含：

```json
{
  "status": "passed",
  "milestone": "R1-A",
  "viewerWriteStatus": 403,
  "projectIsolation": "passed",
  "auditPrivacy": "passed"
}
```

该验证会真实检查：

- 功能模块唯一 key、排序、停用；
- `/orders/<数字>/<UUID>` 保存为 `/orders/:id/:id`；
- 页面不能引用其他项目的功能模块；
- 工作流草稿、激活后不可原地修改、新草稿版本递增；
- viewer 写 API 返回 403；
- 模块、页面、工作流每次修改产生审计；
- 审计中不保存 selector、trigger config、token 或 query。

如出现 `ERR_PNPM_RECURSIVE_RUN_NO_SCRIPT`，不得继续手工验收。保留完整输出并确认当前分支后重新运行 `./scripts/dev up`；R1-A 的 tools-profile 镜像会由命令强制重建。

## 3. 管理员手工验收

打开 `http://localhost:4173`，使用：

| 权限       | 邮箱                     | 密码               |
| ---------- | ------------------------ | ------------------ |
| 管理员     | `admin@example.invalid`  | `LocalAdmin-1234`  |
| 只读查看者 | `viewer@example.invalid` | `LocalViewer-1234` |

密码连接符必须是 ASCII `-`。

### 3.1 正式入口与范围边界

1. 管理员登录后，在左侧点击“指标管理”；
2. URL 应为 `/projects/<projectId>/metrics?range=7d&tab=analysis-objects`；
3. 页面顶部只有“分析对象”可用；“运营指标、质量指标、分数管理、版本库”明确标记为后续里程碑且不可点击；
4. 打开旧“运营指标配置”，模块和页面只能查看，页面提示已迁移并能跳回“指标管理 → 分析对象”。

预期：功能模块和页面只有一个正式可编辑入口；旧运营目标/profile 暂时保留，不形成第二套分析对象编辑页。

### 3.2 功能模块闭环

1. 在“功能模块”TAB 新建：
   - `moduleKey`：`manual_energy_management`
   - 名称：`手工验收能源管理`
   - 关键度：`1.2`
   - 顺序：`5`
2. 修改名称和顺序并保存；
3. 停用，再重新启用；
4. 尝试再次创建相同 `moduleKey`。

预期：列表按顺序显示；修改和状态立即刷新；重复 key 返回冲突，不生成第二条记录。

### 3.3 页面定义与未归类 route

1. 切换到“页面”；
2. 点击“新建页面定义”，route 输入 `/orders/983721`；
3. 页面必须预览“保存为 `/orders/:id`”；
4. 填写名称、所属功能模块、模板、核心状态、关键度和频率后创建；
5. 修改所属模块、模板和核心状态并保存；
6. 在“未归类 route”列表选择一项，点击“创建页面定义”；
7. 停用并重新启用新页面。

预期：动态数字/UUID/长 opaque segment 被归一化；query/hash route 被拒绝；页面不能选择其他项目的模块；未归类入口会预填观测 route。

### 3.4 工作流定义与步骤

1. 切换到“工作流”，新建：
   - `workflowKey`：`manual_model_download`
   - 名称：`手工验收模型下载`
   - 归属刚创建的功能模块；
   - 开始策略：首步骤自动创建匿名实例；
   - 超时：600 秒。
2. 保留至少两个步骤，使用上移/下移验证顺序；
3. 第一步选择“稳定选择器适配器”，输入 `.download-button`；
4. 确认页面出现“普通 class 容易随样式变化”的警告；
5. 将 selector 改为 `[data-fi-action="download"]`，警告应消失；
6. 将最后一步设为成功终态，保存草稿；
7. 展开列表核对步骤顺序、step key 和触发类型；
8. 激活 v1；再次编辑并保存，列表应出现 v2 draft，而不是原地修改 v1；
9. 停用并重新启用工作流。

预期：步骤限制为 2–20，step key 和顺序唯一；成功/失败/取消终态必须引用已存在且彼此不同的步骤；超时固定为 `approximate_abandoned`；UI 不提供 DOM 文本采集。

## 4. viewer 权限验收

1. 退出管理员，使用 viewer 登录；
2. 进入相同项目的“指标管理 → 分析对象”；
3. 依次查看功能模块、页面和工作流；
4. 检查不存在“新建、保存、停用、激活”等写操作；
5. 切换项目或直接修改 URL 中的 `projectId`，确认无权限项目返回 forbidden 且不泄露对象数据。

预期：viewer 可以看相同的授权项目元数据和工作流版本，但任何写 API 都返回 403；未授权项目不返回模块、页面、工作流或唯一 key 信息。

## 5. 浏览器自动化回归

本地栈保持启动，安装浏览器后运行：

```bash
pnpm exec playwright install chromium webkit
pnpm test:r1a:e2e
```

预期：Chromium 与 WebKit 均通过管理员“功能模块 → 页面 → 工作流”闭环，以及 viewer 只读流程。R1-A 还更新了 M6 回归，使旧运营目标/profile 与新分析对象入口并存但不重复编辑。
