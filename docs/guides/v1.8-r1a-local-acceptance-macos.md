# v1.8 R1-A UX follow-up 手工验收指引（Apple Silicon Mac）

> 适用分支：`agent/v1-8-r1a-ux-followup`<br>
> 产品基线：`docs/product/requirements-v1.8.md` §9.7、§15.5<br>
> 开发基线：`docs/planning/mvp-plan-v1.5.md` §8.1–§8.5

本指引只验收 R1-A 分析对象定义与配置体验。R1-B 指标字典/公式/DAG/版本库、R4-B workflow collector/实例关联/事实查询和 R6 正式未归类 route 页面都不是本次交付。

## 1. 自动化前置门禁

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm test:r1a
bash -n scripts/dev
```

预期：格式、workspace 边界、事件契约、规范名、lint、类型、全部单元测试及生产构建通过；专项测试覆盖模块关键度删除、selector/operation 配置约束、自然语言说明、权限和 baseline revision 表。

## 2. 从空库启动

确认本地 `frontend-insight-m5` 测试数据可以删除，然后执行：

```bash
./scripts/dev reset --confirm-local-data-loss
./scripts/dev bootstrap
./scripts/dev up
./scripts/dev smoke
./scripts/dev verify-r1a
```

`verify-r1a` 必须输出 `"status":"passed"`，并包含：

- `historicalSemantics: "passed"`；
- `physicalDelete: "not exposed"`；
- `projectIsolation: "passed"`；
- `auditPrivacy: "passed"`；
- `viewerWriteEndpoints: 11`。

该脚本使用真实 MySQL/API 检查 module/page revision effective window、归档依赖、默认过滤、唯一 key 占用、恢复、工作流版本不可变、operation registry、admin/viewer、项目隔离和审计脱敏。

## 4. D1-A 与模块生命周期

1. 进入“指标管理 → 分析对象 → 功能模块”；
2. 检查列表、创建框和编辑框均没有模块级关键度；
3. 新建 `manual_energy_management`，修改名称和顺序并保存；
4. 在仍启用时保存，检查成功提示说明创建新 revision；
5. 直接归档启用模块，应提示先停用；
6. 停用后，如模块仍有页面或工作流，再归档应列出依赖数量；
7. 处理依赖后归档，默认列表隐藏；勾选“显示已归档”后恢复；
8. 再次创建相同 `moduleKey`，应返回明确 409，归档不释放 key；
9. 对 module 发送 `DELETE`，应为 404，不存在产品内物理删除。

页面级关键度必须继续存在于页面编辑抽屉。

## 5. D3-A、D4-A 与页面定义

1. 切换到“页面”，先在顶部模块选择器选择模块；
2. 选择器显示模块名称、状态和页面数；刷新后恢复上次选择；
3. 列表只显示该模块页面，并可按名称或 `pageRoute` 搜索；
4. 点击“新建页面定义”，抽屉应预填当前模块；
5. 输入 `/orders/983721`，应预览保存为 `/orders/:id`；
6. 创建后列表列仅包含页面名称、`pageRoute`、页面模板、核心状态、状态和操作；关键度与频率在抽屉内；
7. 在页面仍启用时编辑所属模块、模板、核心状态、页面关键度或预期频率；开始修改后必须常显准确文案“**不建议频繁修改该字段**”；
8. 控件保持可用且能保存；保存后显示新 revision 提示；`pageRoute` 始终不可编辑；
9. 使用 `GET .../page-definitions?at=<旧时间>` 检查旧名称、模板和模块归属未被当前值重写；
10. 停用、归档、默认过滤、显示已归档和恢复按模块同样验收；归档后相同 `pageRoute` 仍冲突。

## 6. D5-A 未归类 route

1. 页面定义页只显示“未归类 route 临时入口”和待处理数量；
2. 初始为折叠状态，不长期展示大块表格或空表；
3. 展开后可用观测 route 预填页面；
4. 检查存在“前往 R6 页面运营入口（待交付）”跳转和迁移说明。

预期：当前没有实现 R6 正式页面，临时入口仍保留发现能力。

## 7. D6-A 与工作流可理解性

新建工作流并逐步检查：

1. 字段名称是“步骤达成条件”，不是“触发类型”；
2. 显式 SDK 上报没有 `actionKey` 或“受控值”，只读示例包含当前 `workflowKey` 的 `tracker.startWorkflow` 和当前 `stepKey` 的 `reachStep`；
3. 只有选择“元素交互”时出现可键盘聚焦的问号图标；事件下拉只含 `click/change`；
4. 关键限制同时常显在 helper 和右侧上下文面板，不能只看 tooltip 才能完成配置；
5. 普通 `.class` 显示脆弱性警告，ID/`data-fi-action` 不误报；
6. 请求完成、页面生命周期、显式 SDK、元素交互、operation 终态各自显示主体、判定时机、不能推断内容和自然语言预览；
7. 桌面端是编辑区 + 右侧说明区；将窗口缩窄到 760 px 以下，当前步骤说明折叠到步骤下方；
8. 激活 v1 后保持工作流启用并点击编辑，保存应创建或打开 v2 draft，v1 不被原地修改；激活 v2 时 v1 的 effective window 才关闭。

## 8. operation 终态

1. 选择“operation 终态”；
2. “匹配的 operation”只列出已登记、启用且 `operationLifecycleEnabled=true` 的标识；
3. 必须同时保存 `operationKey` 与 `succeeded/failed/canceled`；不能只保存状态，也不能选择 `completed`；
4. 只读示例使用 `workflow.startOperation(...)`；
5. 页面必须明确写出“当前 R1-A 只配置定义；关联采集在 R4-B 交付”；
6. 页面必须明确说明独立 `tracker.startOperation(featureKey)` 不能驱动 workflow step；
7. 整个 workflow 的成功终态仍标为 `completed`，与 operation 状态分层。

## 9. 权限、隔离、审计与隐私

1. 使用 viewer 登录，三个 TAB 可读，但不存在创建、编辑、启停、归档、恢复、激活按钮；
2. 直接调用 module/page/workflow 创建、更新、归档、恢复或草稿 API，全部返回 403；
3. 页面/工作流引用其他项目模块返回 404/受控引用错误，不泄露对象；
4. `audit_logs` 包含创建、revision 更新、归档、恢复、草稿和激活动作；
5. 审计 metadata 不包含 selector、trigger config、token、query、DOM/表单文本或业务对象 ID。

## 10. 双浏览器 E2E

本地栈保持运行：

```bash
pnpm exec playwright install chromium webkit
pnpm test:r1a:e2e
```

Chromium 与 WebKit 都必须通过：admin 完整 UX/lifecycle、viewer 403 和窄屏说明区测试。不得只运行或只报告一个浏览器。
