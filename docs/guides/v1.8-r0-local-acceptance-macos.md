# v1.8 R0 本地验收指引（Apple Silicon Mac）

> 适用分支：`agent/v1-8-r0-refactor-contract`<br>
> 产品基线：`docs/product/requirements-v1.8.md`<br>
> 开发基线：`docs/planning/mvp-plan-v1.5.md` R0

R0 只验收规范名、contract v3、ADR、空库基线、seed 和测试骨架，不验收新信息架构页面。

## 1. 静态验收

```bash
pnpm install --frozen-lockfile
pnpm contract:check
pnpm canonical:check
pnpm test:r0
pnpm typecheck
pnpm build
```

预期：生成物无差异；旧名扫描通过；v3 valid/golden 通过；v1/v2、旧字段、旧 event alias、隐私负例被拒绝。

## 2. 明确重置本地测试数据

R0 不支持旧测试卷升级。先确认当前 Compose 项目只有可丢弃的本地数据，再执行：

```bash
./scripts/dev reset --confirm-local-data-loss
./scripts/dev bootstrap
./scripts/dev up
```

`up` 只有在 migration 和 R0 seed 都成功后才算完成。必须看到下面两行；出现任何 `ERR_PNPM_RECURSIVE_RUN_NO_SCRIPT` 或 seed error 时立即停止，不要继续登录或 smoke：

```text
[frontend-insight:r0] R0 users, project, canonical entities, workflow and metric definitions are ready
[frontend-insight:r0] Local admin: admin@example.invalid / LocalAdmin-1234 (ASCII '-' hyphen)
```

管理端地址为 `http://localhost:4173`。本地固定账号如下：

| 权限       | 邮箱                     | 密码               |
| ---------- | ------------------------ | ------------------ |
| 管理员     | `admin@example.invalid`  | `LocalAdmin-1234`  |
| 只读查看者 | `viewer@example.invalid` | `LocalViewer-1234` |

密码中的连接符必须是 ASCII hyphen-minus `-`（U+002D），不能使用外观相近的 `–`、`—` 或 `−`。建议直接复制上面代码格式中的密码。

不带 `--confirm-local-data-loss` 的 reset 必须失败；普通 `down` 必须保留 named volumes。reset 输出的卷必须都带精确 Compose project label，不得删除其他项目卷。

`up` 应从空库执行 MySQL/ClickHouse 各一个 `001_v18_baseline.sql`，然后运行 R0 幂等 seed。第二次执行以下命令不得新增 migration 版本或重复业务定义：

```bash
./scripts/dev seed
./scripts/dev seed
./scripts/dev smoke
```

`seed` 和 `smoke` 会强制重建各自的 tools-profile 镜像，避免复用 R0 之前的旧镜像。`smoke` 会只读核对 seed 快照，并用上述管理员和查看者账号真实调用登录 API；它不得自行补写用户或项目数据。

## 3. 数据库核对

```bash
docker compose --project-name frontend-insight-m5 \
  --env-file .env.m5 \
  --file infra/compose/m2-m4.compose.yml \
  --file infra/compose/m5.compose.yml \
  run --rm --build verifier
```

预期：

- 两个 `schema_migrations` ledger 都只有版本 1，重复 bootstrap 的 `applied` 为空；
- MySQL 存在 `projects.app_id`、`modules`、页面、workflow、指标版本、指标定义、两类 score、probe 和外部接口凭证表；
- ClickHouse `raw_events` 存在 v3 规范列及 workflow/error 列，90 天 TTL 与月分区生效；
- v3 smoke 数据可按 request ID 查询，非 v3 数量为 0，非空 `user_id` 均为 64 位 HMAC。

## 4. 链路 smoke

```bash
pnpm test:r0:e2e
```

该测试要求本地栈已启动：合法 v3 返回 202 且声明仅支持 `[3]`，v2 返回 `SCHEMA_VERSION_UNSUPPORTED`。随后在浏览器 Network 中抽查一次 demo 上报：每个事件都有完整公共上下文，URL 无 query/hash，功能动作是 `event=custom` 与受控 `payload.name`。

该测试还会用文档中的管理员邮箱和 ASCII 密码调用登录 API。如果这里失败，即使页面和健康检查可打开，也不得签字通过。

## 5. 常见失败定位

### `ERR_PNPM_RECURSIVE_RUN_NO_SCRIPT: seed:r0`

这表示 Docker 正在复用 R0 之前构建的旧 seed 镜像，而不是当前分支代码。修复后的 `./scripts/dev seed` 会自动带 `--build`；正常情况下不需要手工删除镜像。先确认分支和最新提交，再重新执行：

```bash
git branch --show-current
git pull --ff-only
./scripts/dev seed
./scripts/dev smoke
```

如果仍失败，请保留 `./scripts/dev seed` 的完整终端输出；不要把该错误当作可忽略的遗留提示。

### 页面可打开但登录返回 401

页面健康只证明 Web/API 进程已启动，不证明 seed 成功。先检查 `up` 是否打印 seed 成功行，再运行 `./scripts/dev smoke`。同时确认密码使用 ASCII `-`。连续输错五次会触发 15 分钟登录限流，此时应重启 API 容器或等待限流窗口结束后再测。

## 6. 人工签字项

- ADR-014 至 ADR-018 均为 Accepted，且无 stop 条件被触发；
- canonical manifest、生成类型、schema、系统指标 seed 和文档表内容一致；
- `docs/contracts/v1.8-r0-deletion-checklist.md` 的 R0 项均已删除，页面类延后项均标明替代里程碑；
- seed 含项目、模块、页面、workflow、全部附件 metric key、运营分和质量分；
- 管理员和只读查看者均能使用文档中的 ASCII 密码登录；
- 运营/质量手算、公式、workflow 与隐私五组 fixture 可人工复核；
- 未新增 R1 及以后页面，也未以大范围历史回归替代 R0 验收。
