# v1.8 R3 Apple Silicon Mac 手工验收

本指引追加 R3，不覆盖 R1/R2 指引。R2 已由用户于 2026-09-15 确认验收通过；该日期仅表示确认。R3 手工验收仍待用户确认，不自动合并或进入 R4。

## 启动与 SHA

使用 Apple Silicon Mac、Docker Desktop、Node 24、pnpm 11.15.1。建议 Docker 至少 8 GB 内存。默认保留已有 Docker 数据卷和数据库。先确保当前工作区修改已自行保存，再切换 R3 分支：

```bash
git fetch origin
git switch agent/v1-8-r3-project-overview
git pull --ff-only origin agent/v1-8-r3-project-overview
git rev-parse HEAD
pnpm install --frozen-lockfile
./scripts/dev bootstrap
./scripts/dev up
./scripts/dev smoke
```

最终 HEAD 必须与交付消息及 R3 Actions 的 `head_sha`、checkout 步骤和 `r3-evidence.json.testedCommit` 一致，不能用较早提交成功代替。当前最终 SHA/Actions 以 [R3 results](../progress/v1.8-r3-results.md) 最终验证记录为准。尚未最终验证时，不将工作分支视为已完成验收准备。

网页 `http://localhost:4173`。管理员 `admin@example.invalid` / `LocalAdmin-1234`；只读用户 `viewer@example.invalid` / `LocalViewer-1234`。这是仓库既有本地测试账号，仅用于本地环境。账号切换使用独立浏览器窗口或先退出。

## 真实入口与项目框架

1. 两个角色分别登录，默认到 `/projects`，根路由仍回全部项目。搜索、每页数量、下一页、刷新和浏览器后退均保持原上下文。
2. 管理员新建项目，查看定位卡片；新项目只有默认草稿，不能假定双分数可计算。点击进入项目到 `/projects/:projectId/overview`，保留列表的显式 from/to、env 以及返回位置。
3. 左上项目名与返回全部项目，五个正式导航依次为概览、业务分析、页面分析、指标管理、设置。业务/页面/设置显示所属阶段说明，不跳旧同名页面。右上公共时间、项目 IANA 时区、环境、账号、退出均可用。
4. 进入指标管理：分析对象/运营指标/质量指标/版本/分数管理 TAB 和现有定义、review、激活、审计流程保留。返回概览，再返回全部项目，搜索/分页/创建定位与进入前相同。
5. 项目 URL path 是上下文权威，页面没有全局项目下拉。安全已授权深链接可刷新恢复；登录 redirect 的外站地址继续拒绝。未经授权项目显示无项目权限，不显示项目名、指标、版本或内部错误。

## 时间、环境与 URL

- 7/30 天为 day，90 天为 week，180/365 天为 month。默认最近 7 个本地日期（含今日至当前瞬时），周一分桶。此为有记录的实施默认，非补写用户批准，见 [decisions](../progress/v1.8-r3-decisions.md)。
- 从 R2 进入的显式 `[from,to)` 不变；纽约、上海项目显示各自本地边界。只有切换预设才生成新的项目日历范围。
- custom 输入项目本地时间，最长 13 个日历月，月末钳制；结束不含。DST 重叠取较早瞬时，不存在的本地时刻向后调整。用纽约 2026-03-08 和 2026-11-01 验证 23/25 小时日桶，90 天周、180 天月中首尾桶明确标为部分桶。
- env 单选 prod/staging/dev 并写入 URL。修改时间/env、雷达展示或趋势选择后刷新、前进、后退，核对值与请求 query 一致；修改 URL 的 project query 不得覆盖 path。

## 双分数、雷达与下钻

1. 真实环境分别查看运营/质量 active 版本、effectiveAt、配置与事实可用状态。不可用显示“—”和具体原因，不能把配置完整当作得分存在。真实数值 0 仍显示 0。
2. 雷达只含 0–100 维度分；下方表格是文本等价。定义不足 3 维如实显示，不能造维度。至少两个可用维度才判断最低维度；不足时提示不能判断。
3. 展开雷达展示设置，选 3–6 维，URL 改变、总分/权重/版本保持。viewer 可使用只读筛选。公式修改进入指标管理创建草稿、review、激活，不能从雷达改变公式。
4. 点击分数解释，检查目标、权重、加权贡献、样本、缺失原因与血缘。键盘 Tab 在抽屉内移动，Escape 关闭，焦点回触发按钮。总分不可用时仍保留可得的定义和原始叶子信息。

## 指标与趋势、告警

- 指标从 active 运营版本的 overview bindings 来。管理员进入“运营指标”展开“概览展示指标（版本化）”，保存到草稿，review 后激活；viewer 无保存能力，伪造 PUT 应返回 403 和 requestId。not_collected 不能绑定。
- 卡片显示名称/值/单位/描述/样本/时间/状态。多卡区域可获得键盘焦点并左右滚动，按钮可逐项 Tab 到达。
- 同单位最多 4 条非堆叠折线，混合单位分图。展开等价表查看完整桶、null 原因、真实 0；缺口不跨线。激活边界拆分区段，历史区段不挂当前版本，不自动重算历史。
- 固定告警区分已触发、所查样本未触发、样本不足和无法评估。证据抽屉提供规则、事实、样本、观察窗口、project/env。项目级链路告警不冒充当前 env 的健康证据。

## 隔离正常 fixture 与真实不可用

R3 专项集成创建独立项目，不更改前序测试项目的 active/draft。完整 CI 必须先运行前序回归，再运行 R3：R1-B 有全库约束检查，不能在后续阶段写入评分快照后执行。以下命令不清库，但会追加测试数据和审计记录：

```bash
pnpm check
pnpm test:r3
./scripts/dev verify-r3
pnpm exec playwright install chromium webkit
pnpm test:r3:e2e
```

`artifacts/r3-integration.json` 记录独立项目 ID、真实存储验证及性能样本。该项目原始事件明确是合成观察，不能称真实业务分数。浏览器 normal fixture 使用拦截的测试响应，显示“隔离 fixture：非真实业务数据”，复用 R1-C evaluator 产生 76.15/72.95 正常分数，仅用于自动验证雷达/贡献/趋势/零值/缺口/告警。生产 API 不提供 fixture 开关；不要为手工看正常图而向业务数据库注入假评分事实。可用 Playwright UI 检查隔离流程：

```bash
pnpm exec playwright test --config playwright.r3.config.ts --ui
```

真实项目仍可能没有两类总分；验收应查看为何不能判断、缺哪些事实和配置，而不是期待合成数值出现。

## stale、失败与权限负向

同 URL 点击刷新，慢响应期间保留上次数据并标记 stale 与旧版本身份；失败保留旧数据、错误 request ID 和重试按钮。变更 project/env/range/趋势后不可把旧值改标新选择。下钻时切换上下文关闭旧证据；激活新版本后刷新替换整体读模型。R3 双浏览器专项以可控延迟/失败响应验证乱序，真实 API 同时验证独立版本与重激活。

viewer 直接请求未授权 `/api/projects/:id/overview` 应 403；非法 env/额外 query/过长范围/未绑定指标应 400；不能从错误体取得项目名称或敏感详情。检查浏览器 CSP 无 unsafe-eval，访问日志不含 token、payload、搜索值。

## 性能与前序回归

R3 集成对 7/30/90/180/365 天和允许的长 custom 范围，以及 13 个月的 day/week 桶，共八组分别预热 5 次，采样 40 次，用排序后的 `ceil(n×0.95)-1` 取 p95，目标≤2秒。附件保留全部原始样本、环境、SQL/CH 查询数与扫描量；浏览器附件记录从进入到首次可用的耗时。raw_events 物理 TTL 是 90 天；长范围包含缺事实区段，不能把本次延迟当作生产容量证明。

完整验收在一次性空库环境按下列 CI 顺序运行，不能先运行 R3 再追加 R1-B：

```bash
./scripts/dev verify-r2-upgrade
./scripts/dev verify-r1b
./scripts/dev verify-r1a
pnpm test:r1b:e2e
pnpm test:r1a:e2e
./scripts/dev verify-r1c
pnpm test:r1c:e2e
./scripts/dev verify-r2
pnpm test:r2:e2e
./scripts/dev verify-r3
pnpm test:r3:e2e
```

R2“暂到 metrics”仅改成正式 overview 落点，其余搜索/分页/创建/权限/返回、防抖冻结时钟与精确浏览器定位保留。保留数据迁移使用 `./scripts/dev verify-r2-upgrade`，它要求新建独立升级验证数据库，已有该数据库时先检查历史结果，不删除业务数据。

## 排错和停止

`./scripts/dev status` 查看服务；`./scripts/dev logs api`、`./scripts/dev logs consumer`、`./scripts/dev logs web` 查看问题。无权限先核对角色和 membership，不放宽授权。无分数先核对 active、bindings、计算窗口/effectiveAt 和缺失事实原因，不改公式或用 fixture 补值。CSP 错误核对安全 canonical 子路径构建产物，不增加 unsafe-eval。退出使用 `./scripts/dev down`，保留数据卷。
