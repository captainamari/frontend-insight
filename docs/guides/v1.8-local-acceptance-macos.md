# v1.8 最终本地验收（macOS）

本指南是待执行步骤，不是验收通过记录。适用于可销毁的本地测试栈；R6 朋友验收、R7 真实规则批准分别记录。Ubuntu 22.04 生产环境使用 [生产指南](production-ubuntu-22.04.md)，绝不能运行本指南的 reset、seed 或故障注入。

准备：Apple Silicon Mac、Docker Desktop（daemon 建议 16 GiB）、Git；本地运行 Playwright/静态检查需 Node 24、pnpm 11.15.1。容器化应用不依赖宿主 Node 26。所有命令在仓库根目录，先核对 Docker context 指向本地测试环境：

```bash
git status --short
git rev-parse HEAD
docker context show
docker version
docker compose version
./scripts/dev doctor
pnpm install --frozen-lockfile
pnpm exec playwright install chromium webkit
```

不要覆盖未提交修改。将实际代码 SHA、Mac 型号/架构、Docker/Compose 版本、每步结果及脱敏截图记入验收记录。Linux CI 只验证 Linux；此处实际 Mac 运行尚待 Owner。

## 1. 空库重建与登录

**以下会删除 frontend-insight-m5 本地测试卷。先确认没有业务数据。**

```bash
./scripts/dev reset --confirm-local-data-loss
./scripts/dev bootstrap
./scripts/dev up
./scripts/dev smoke
open http://127.0.0.1:4173
```

使用 `admin@example.invalid` / `LocalAdmin-1234`；viewer 是 `viewer@example.invalid` / `LocalViewer-1234`。预期登录进入全部项目。失败执行 `./scripts/dev status` 与 `./scripts/dev logs api`，确认构建/seed 成功、没有使用旧镜像。不要以反复 reset 修复保留数据环境。

## 2. 入口页创建与查找项目

创建名为“R8 手工验收”的项目、时区 Asia/Shanghai，Origin 填 `http://127.0.0.1:4173`（设置测试按钮）与 `http://127.0.0.1:4174`（demo）。查找名称、刷新并复制链接；进入后只有五个项目模块，返回全部项目保留列表上下文。

```bash
pnpm test:r2:e2e
pnpm test:r8:e2e
```

预期 admin 可创建、viewer 不可写；两个项目切换不串数据。出错保存 request ID，核对成员授权和 URL 中 projectId，不能只看隐藏按钮。

## 3. 配置模块、页面与工作流

指标管理 → 分析对象，创建模块、页面 `/r8-demo`、工作流；配置稳定 stepKey、顺序及终态。逐字输入不丢焦点；显式 SDK 触发优先。已有定义的修订与激活按版本保存。进入页面运营的未归类路径，管理员点预填配置后返回原页面上下文。

```bash
pnpm test:r1a:e2e
```

预期 viewer 只读；禁用/归档不抹除历史。失败检查稳定 key、所属模块与实际 SDK operation registry；不能用业务订单 ID 作为实例 ID。

## 4. 创建并激活两类指标版本

分别建立运营和质量草稿，查看指标定义/单位/真实分母，配置展示绑定和评分叶子；运营草稿必要时点击“同步页面使用定义到草稿”。执行试算、评审、激活；再次改动只能生成新草稿。保存旧版本 ID，核对历史结果仍固定旧版本。

```bash
pnpm test:r1b:e2e
pnpm test:r1c:e2e
```

预期非法公式/DAG 拒绝；无目标、样本不足、未采集各自保留原因。失败核对当前草稿/active、review 是否在最近改动后产生，不修改 golden 使测试通过。

## 5. 项目概览的两类分数

查看独立运营/质量分数、维度贡献、门槛、版本和血缘，切换环境与 7/30/90/180/365 天及最长 13 个月自定义范围；表格和图形等价，跨版本不拼成单一分数。新测试项目无数据时不可得满分。

```bash
./scripts/dev verify-r3
pnpm test:r3:e2e
```

失败区分数据状态、定义版本边界和评分资格；保留 unavailable 原因，不把无数据写为 0。

## 6. 功能模块指标

业务分析核对模块、已归类页面、版本化指标、趋势及组织目录观察边界；未归类流量不静默进入模块分数。目录人数不等于活动完整性证明。

```bash
./scripts/dev verify-r4a
pnpm test:r4a:e2e
pnpm test:r4c:e2e
```

长范围超事实保留期应说明不可用。失败看来源/目录覆盖、版本及 retention，不临时补假分母。

## 7. 多阶段工作流

打开 `http://127.0.0.1:4174` 的受控演示，执行两次并发开始，分别成功、失败/取消；检查业务分析中的实例、终态、各阶段耗时。使用配置页生成的实际 SDK 契约；不把首次开始作为成功。

```bash
pnpm test:r4b:e2e
```

预期随机实例不串联，乱序/重复终态按既有规则显示，超时为近似放弃。失败核对 workflow definition version/stepKey，不人工补事件伪造终态。

## 8. 错误与性能样本

在受控 demo 触发 JS、资源、API 失败及性能事件；本地 fixture 使用模拟敏感串，真实凭证不得输入。检查事件先脱敏后发送、正常请求也形成分母。

```bash
pnpm test:r5a:e2e
node tools/r5a-load.mjs
```

预期质量定义、覆盖诊断与错误类型匹配。HTTP 202 只证明接收；必须等待 storage/API。性能报告明确接收响应、可查询延迟上界与查询耗时各自含义。

## 9. 页面质量与运营分析

同一项目/env/pageRoute/范围切换质量和运营 TAB、复制 URL、刷新与返回。检查错误明细键盘操作、筛选/分页与安全上下文；运营侧检查匿名/已识别构成、日历周期、DST、会话、时长缺失、真实零值和覆盖率。

```bash
pnpm test:r5b:e2e
pnpm test:r6:e2e
node tools/r5b-storage-privacy.mjs
```

缺失 leave 不补零，多周期 DAU/WAU/MAU 不求和冒充单值。超 50,000 返回事件或扫描预算应显式拒绝；缩短范围用于定位，不声称已满足更大容量。

## 10. 探针与外部接口

按 [R7 指南](v1.8-r7-acceptance.md) 配置 Origin，实际运行设置页 SDK 示例，测试事件到“可查询已证实”；查看真实探针分母。外部接口初始关闭，启用后一次显示凭证，验证 scope/轮换/撤销，刷新不可读回明文。

```bash
pnpm test:r7:e2e
./scripts/dev verify-r7
```

不要把 TEST ONLY 的批准 fixture 当真实批准。真实异常规则仍默认关闭；multi_ip/permission_denied 保持 not_collected。失败检查精确 Origin、blocked、scope 与时间边界。

## 11. viewer 只读

退出并登录 viewer，遍历六模块；不能创建项目、改配置、发布版本、签发外部凭证。直接 HTTP 写请求也应 403。无成员授权项目的深链接不可读。

```bash
pnpm test:r8:e2e
```

预期读权限不等于审批人身份；越权数据不在 UI/API。保存脱敏拒绝码/request ID，不复制 token。

## 12. 数据状态、隐私、故障与恢复

仅对上述可销毁本地栈执行：

```bash
pnpm check
bash scripts/m7 fault all --confirm-disruption
bash scripts/m7 release-drill --confirm-disruption
./scripts/dev smoke
./scripts/dev status
```

预期停止 consumer 后队列恢复可查，Kafka 不可用时拒绝而不是假接收，ClickHouse 不可用时 readiness 失败；恢复后数据及业务读 API 可用。演练比较 MySQL、原始事件和持久证明的恢复前后导出，短引用按 ADR-020 不备份。失败保留脱敏错误和服务状态；不要将只生成归档文件当作恢复成功。

生产 Compose 的真实初始化、非 root/只读、密钥隔离、TLS 双浏览器、保留卷及备份恢复由 `production-deployment.yml` 在隔离 runner 执行；不要在生产机运行其测试 harness。验收结束可 `./scripts/dev down` 保留本地测试卷。

完成十二步后由执行者逐项签署结果；工程通过、自动化通过、手工通过和业务批准分别记录。任何缺项仍是最终 No-Go。
