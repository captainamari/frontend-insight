## 两角色完整操作

1. 普通登录应到 `/projects`；根路由、已登录访问 `/login` 也到全部项目。页面无需先选择项目，没有旧首页抢占。退出后用站内授权指标深链接登录，应安全返回；外部 redirect 应被忽略。
2. 搜索中文项目名称，连续输入只在停止300 ms后发起摘要请求；清空恢复列表。搜索无结果保留文本和清空入口。断网/服务异常有错误与重试，恢复后可继续。
3. 选12/24/48，前后翻页；URL 的 search/page/pageSize/env/range/from/to 与界面一致，刷新、前进、后退保留选择。快速换搜索、页码、环境，旧响应不能覆盖新状态。越界页定位最后有效页。
4. admin 用键盘打开「新建项目」，焦点进入名称。填写名称、IANA 时区、精确 Origin、保留天数、两个版本化初始模板。Origin 如 `http://localhost:4173`；带路径/query/hash/星号应失败。故意输入无效值或断网提交，输入保留；同输入重试不重复创建。
5. 成功后搜索与页码更新，提示新项目名称并将焦点定位卡片，即使原先搜索/页不包含新项目也能找到。两类分数应为 `—`，模板草稿未确认，不会自动制造 active 分数。进入项目后查看两个独立草稿，R1-C 的配置确认/review/激活门禁仍有效。
6. 卡片查看名称、运营/质量各自版本和上下文、主状态、链路及作用范围、真实最近接收时间、全部不可用原因。不同项目时区有各自本地边界；同一列表共享明确 UTC 瞬时范围。切换 prod/staging/dev 后最近观察不能串环境。

## 明确隔离的正常 fixture 与真实不可用

当前真实工作流/质量分母/env完整性未齐，真实项目总分为 `—` 是可能且正确的结果。不要向真实项目注入正常分数。专项浏览器测试拦截摘要响应，只在测试页面展示标为「合成」的0/60/80/80.01/85分、normal/alert/no_data/partial/broken/delayed；截图用于边界检查，不写入真实评分库。

规则：80 告警，80.01 在另一分数也 >80 且 healthy 时正常；85绿色、60黄色、0红色、null灰色。broken+缺配置、低分+缺样本保留全部原因，主状态告警。未知链路不自动 healthy。

## 排错与反馈

| 现象                        | 处理                                                               |
| --------------------------- | ------------------------------------------------------------------ |
| Docker/架构错误             | 启动原生 arm64 Docker Desktop，执行 `./scripts/dev doctor`         |
| 新路由/接口404或缺表        | 核对SHA，重新 `up` 构建并检查迁移；不只刷新旧镜像                  |
| 创建409                     | 相同重试键对应不同输入；修正输入会生成新键，保持原输入可安全重试   |
| 模板/配置不可激活           | 初始化不等于业务已确认；按原 R1-C 指引完成配置确认、review         |
| 真实分数不可用              | 查看版本/范围/来源/样本原因；R4-B/R5-A/R6负责后置事实，不补0       |
| 链路 unknown / 事实源不可用 | 区分 env 未验证与CH故障；检查 `./scripts/dev logs api` 和存储状态  |
| 异常响应                    | 记录 requestId、SHA、角色、URL、步骤和截图；不附token或事件payload |

最后 `./scripts/dev down` 保留数据。分别反馈实现体验、自动化证据、真实集成证据及手工结论；只有 Jesse 的明确确认能完成本次手工验收。代理不合并、不进入R3。
