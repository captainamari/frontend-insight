# R6 page operations handoff

Use the existing Docker deployment and migration commands. No new database migration or reset is required for R6.

1. As admin, open metric management, create an operational draft from the chosen version, inspect the new page usage definition, configure page display bindings, and use the existing review/activation flow. Old active snapshots are not silently upgraded. A draft can be explicitly previewed with `versionId`.
2. Open the formal page analysis entry. Switch between quality and operations with the same project, environment, route and time range. Reload/share the URL and rapidly change page routes; stale results must not overwrite the last selection.
3. Check identified/anonymous composition, PV/UV/VV, calendar series, duration coverage and missing reason. Missing page_leave must not appear as zero duration. Multiple calendar periods have no summed DAU/WAU/MAU scalar. Hour-of-day uses project timezone.
4. Inspect page template, module, core state, expected frequency, revision effective range and page-linked workflow aggregates. Unclassified routes have an admin configuration entry; viewer sees read-only information.
5. Empty routes/environments show no data, not invented zero. Bounce rate is diagnostic only. No raw identity, payload, query, header, body or DOM appears in API/UI.
6. For more than 50,000 matching events or one million scanned rows, shorten the query range. The budget is a protective limit; performance evidence is limited to its stated cohort.

Automated real services and Chromium/WebKit evidence is recorded by `.github/workflows/v1-8-r6.yml`. This guide is not a claim that manual checks occurred.
