## 管理员准备专用示例项目

从全部项目创建专用验收项目，时区选实际项目IANA时区，Origin登记 `http://localhost:4174`（使用127.0.0.1时也登记对应Origin）。创建一个启用模块及 `/` 页面。创建 feature `model_download`，启用 operation lifecycle；工作流条件中的operationKey复用这个标识。

创建下表的两个工作流，先保存草稿，再激活。所有步骤按表内顺序从1编号。失败/取消步骤可留空，业务handle可显式fail/cancel。超时状态固定 approximate_abandoned。

| 工作流                  | 步骤                                                                          | 触发条件                                                                                 | 成功步骤           | 超时  |
| ----------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | ------------------ | ----- |
| dashboard_property_view | property_selected → data_loaded → property_rendered                           | explicit_sdk；network_request GET `/workflow-demo-data.json`；page_lifecycle loaded      | property_rendered  | 10秒  |
| admin_model_download    | download_requested → request_accepted → transfer_started → transfer_completed | 前三步explicit_sdk；最后operation_terminal，operationKey=model_download，state=succeeded | transfer_completed | 600秒 |

在demo首页填写项目appId，点击“加载工作流配置”。不填写管理token；Origin/appId/env控制安全配置分发。SDK 0.5.0只上报受控键、随机实例、版本和阶段。

## 三类结果必须分别验收

- **真实不可用**：未安装/尚未观察到兼容SDK、没有定义、只有草稿、没有事实、来源缺失分别解释。长范围如实披露90天物理保留期。没有可信完整业务活动来源时，R4-A比例仍不可用，不把page_view-only UV当完整分母。
- **真实partial**：真实SDK事实可显示已观察阶段/耗时；覆盖未知、未识别或冲突样本继续披露。评分入口已读取冻结工作流版本样本；它不会把未知覆盖变成合格叶子或补齐质量/使用总分。
- **隔离正常数值fixture**：`pnpm test:r4b`验证90项目日历日近似的可用estimated路径、分母0、DST/边界、手算分位数与池化加权评分；fixture不进入生产查询。不得把纯fixture写成真实SDK链路通过。

## 业务开发者选择接入方式

管理者登记模块、页面、operationKey和不可变工作流版本；业务开发者负责业务成功判定与显式实例关联。可运行实现为 `apps/demo-app/src/WorkflowDemo.vue`，在仓库demo中直接操作；完整浏览器入口为 `pnpm test:r4b:e2e`。

```ts
const response = await fetch(collector + "/workflow-config", {
  method: "POST",
  credentials: "omit",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({ appId, env: "dev" }),
});
if (!response.ok) throw new Error("WORKFLOW_CONFIG_UNAVAILABLE");
const config = await response.json();
const tracker = createTracker({
  appId,
  env: "dev",
  release,
  endpoint: collector,
  registeredFeatures: config.operationKeys,
  workflowDefinitions: config.definitions,
});
tracker.setUser(opaqueInternalUserReference); // 规范身份；不传姓名/邮箱
const workflow = tracker.startWorkflow("admin_model_download");
workflow.reachStep("download_requested");
const operation = workflow.startOperation("model_download");
// 收到业务请求确认和第一块有效数据时分别reachStep。
// 响应流完整结束且校验成功后：
operation.succeed(); // 仅本实例且operationKey/state匹配才达成transfer_completed
```

collector为完整事件地址，例如 `http://localhost:4174/v1/events`。真实宿主需使用部署的SDK包/ESM，不使用eval或unsafe-eval。实例ID只由SDK创建；payload不是任意业务对象入口，关联operation的payload必须为空。失败用受控reasonCode调用operation.fail，明确主动中止才cancel。独立 `tracker.startOperation` 不会驱动任何工作流。

显式reachStep用于业务代码已知达成的explicit_sdk步骤。关联operation用于已有operation生命周期且需严格匹配终态的步骤。selector用 `workflow.bindInteractions(scopedRoot)`，仅稳定ID/data-fi-action，不扫描全DOM。网络用 `workflow.observeNetwork(stepKey, {method,pathPattern}, execute, businessPredicate)`；生命周期用 `workflow.bindPageLifecycle(target)`，业务渲染后向该target派发 `fi:page-loaded`。两者均需明确opt-in，返回的解绑函数在宿主卸载时调用。

刷新后用 `tracker.getActiveWorkflows(workflowKey)`取得同受控session中恢复的handle；三个并发实例仍有三个handle，不能按最近一个猜关联。业务需要恢复“哪个任务”的语义时必须在宿主自身维护受控对应关系，不上传业务对象ID。不能可靠确定对应关系时不续接。TTL、session轮换或销毁后不能恢复过期实例。
