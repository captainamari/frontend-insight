## SDK与真实观察

Demo4174输入效率示例appId，安装效率SDK，执行表单与业务结果；代码位于 `apps/demo-app/src/EfficiencyDemo.vue`。它产生3次修改、1次重置、2次提交尝试、1次校验失败；三个独立操作分别success、HTTP200但业务rejected、执行异常unknown。未知不是成功，也不是已确认拒绝。

```ts
const tracker = createTracker({
  appId,
  env: "dev",
  release,
  endpoint,
  registeredFeatures: ["save"],
  forms: {
    enabled: true,
    sampleRate: 1,
    definitions: [{ formId: "edit", fieldKeys: ["status"] }],
  },
  businessOperations: { enabled: true, operationKeys: ["save"] },
});
tracker.setUser(opaqueUserReference);
const form = tracker.trackForm("edit");
// 宿主绑定自己的事件，仅传入固定字段key；不把DOM事件或字段值传入SDK。
form.change("status");
const attempt = form.submit();
if (!hostValidationPassed) attempt.validationFailed();
const result = await tracker.observeBusiness(
  "save",
  executeHostRequest,
  (result) => classifyInTrustedAdapter(result), // 只返回success/rejected/technical_failure/canceled/unknown
);
form.destroy();
```

同一formId重复安装复用handle；重试调用新submit；一次提交的validationFailed重复调用不重复计数。不同formId并发隔离。destroy/SPA导航/身份变化结算一次。采集开关默认关闭；事件使用现有有界队列和8KiB上限；字段最多50个、并发表单10个、每生命周期动作计数10000，超限显式标记。字段key仅参与白名单判断，事件只上传总次数，SDK从不读取值、标签、文案或DOM。

宿主请求返回值/原异常保留；分类器抛错只产生unknown。SDK不解析响应正文，不安装全局fetch包装。上面的基本示例不启用重复操作；需要该指标时按下方可信后端示例接入。C04已批准并实施，不需要再次审批。

登录→全部项目→概览→业务分析，选择模块/env/范围。操作效率区查看真实观察计数与明确不可用原因；任务耗时/路径沿用R4-B。组织区无目录显示not_collected；有效目录和受控事实匹配后显示观察人数、编制、比率及模块分布；小于5人时服务端整族抑制。目录配置入口保留analysisReturn，返回原上下文。

未采样受控表单至少5次有效提交时，三个正式结果分别显示；未知、冲突、溢出或采样会阻断正式值。业务失败率需要同范围至少5个已知结果、未采样且兼容的受控操作；历史SDK缺采样声明不可冒充覆盖。这里的来源仅指登记的受控操作，不代表系统全部业务活动。

## 三类状态与检查

- **无目录**：未发布可信名册的项目不能出现编制人数或组织比例。
- **partial**：C01/C02公式已批准；采样或旧版缺采样声明的观察不能当作未采样正式比率，缺开始/冲突/未知/未识别不补0。
- **保护**：隔离4人目录/贡献样本返回privacy_suppressed，人数、比率、时长及排名整族null；兼容闭合桶的6人正常fixture显示观察结果。阈值k=5已批准并在服务端实现。

## 批准后的检查补充

表单累计至少5次提交后结算，查看三个独立观察比率；未提交生命周期单列，不进入比率分子。修改6/提交5=1.2，重置12/提交5=2.4，不截断。含unknown操作时业务拒绝比率为空，明确显示BUSINESS_RESULT_UNKNOWN；不把未知当作成功。展开趋势核对同一asOf和结算/开始cohort。

组织无目录返回TRUSTED_DIRECTORY_MISSING。新目录当日发布不能用于此前历史，当前未闭合桶或迟到期未结束时明确不可用；无需额外配置隐私策略。闭合日/周/月、完整目录版本覆盖及每个受保护分组eligible和贡献人数均至少5时展示partial观察聚合。任一分组不足时服务端整体privacy_suppressed，不仅前端遮数字。缺page_leave只显示PV，时长与时长排名不能当0。

运行 `./scripts/dev verify-r4c` 可验证独立正常目录历史fixture的6人、6PV、6000ms聚合，以及继承的旧消息/历史版本回放。历史日期由测试专用SQL构造，目录导入/发布为真实API，事件为真实Kafka/consumer链路；不要把这些测试资料作为生产目录或实际SDK历史采集证明。浏览器SDK路径运行 `pnpm test:r4c:e2e`。

## 本次重点：重复操作真实链路

管理员先完成上文项目、模块、页面、edit/save登记；业务开发者在**可信业务后端**调用 `createObjectReferenceProvider`，浏览器只接收返回的短期签名引用。该辅助函数缓存当日项目/env密钥，UTC轮换时重新获取；平台管理凭据及密钥不下发浏览器。密钥签发接口只接受已授权项目管理员的后端调用，并拒绝浏览器 Origin / Fetch Metadata，审计只记录项目/env。

本地隔离演示（不使用真实订单）：

```sh
pnpm build
export FI_PROJECT_ID="替换为隔离项目UUID"
export FI_API_URL="http://127.0.0.1:3000"
# 输入用于该隔离项目的管理员 access token；不回显，不写入命令历史。
read -rs FI_ADMIN_TOKEN
export FI_ADMIN_TOKEN
node examples/r4c-reference-host.mjs
```

1. 保持该终端运行。打开 `http://localhost:4174`，输入隔离项目appId。
2. 点击“从隔离后端获取引用”，然后“安装效率SDK”。如后端返回503，检查项目授权和短期token有效性，不打开payload日志排错。
3. 点击“执行表单与业务结果”一次：同一对象发生3次真实受控操作、同一会话；“相关会话”应为 **1/1**，不是3/3。结果包含业务拒绝、成功及未知，重复操作计开始事实，不将未知变成业务拒绝。
4. 业务分析→同一模块→dev→7天。页面显示重复率观察值1；正式值仍为空，原因 `REPEATED_LATENESS_WINDOW_OPEN`。这是当前窗口未闭合，不是失败。
5. 重新执行不会把投递重试计为新操作；真实再次点击会创建新operation实例。跨会话统计仍按用户+会话去重。
6. 正式重复率还要求查询结束后完整48小时回溯/迟到条件、至少5个相关会话、投影回执齐全、90天保留范围兼容。当前新装SDK不要期待立即出现闭合历史值。手算与边界由专项测试覆盖，真实SDK链路由双浏览器覆盖。

业务代码复用同一个operation生命周期：

```ts
const tracker = createTracker({
  appId,
  env: "prod",
  release,
  endpoint,
  businessOperations: { enabled: true, operationKeys: ["save"], sampleRate: 1 },
  repeatedOperations: { enabled: true },
});
// reference 来自宿主可信后端；这里不哈希原始业务ID，不包含服务端密钥。
await tracker.observeBusiness(
  "save",
  () => saveRecord(),
  classifySafeResult,
  reference,
);
```

业务适配器采样率不是1时不纳入重复统计，避免采样改变“至少3次”条件；原表单与业务结果采样仍独立适用。异常继续保持宿主返回值/抛错。单个对象引用不得超过2048字节；复用SDK队列、事件大小和64并发上限。

引用只进入 `frontend-insight.objects.v1` 和 `object_operation_refs`；普通90天raw_events仅保存随机operation关联与服务端校验标志。普通事件与引用用同一Kafka事务提交，消费者按已提交消息读取。短期查询硬性排除接收后48小时的数据，超期回放不会重建引用。Kafka retention及ClickHouse TTL物理删除由后台执行（TTL merge配置60秒，繁忙/停机时可能滞后），不能把逻辑截止宣称为精确到毫秒的物理擦除；不要把短期表加入长期备份。长期仅保留无对象引用的会话回执/命中证据，原始业务ID始终在宿主可信边界处理。

## 保留范围与版本激活前置

90天是按接收时间的物理保留期，并非13个月完整历史。表单、业务失败率和重复率的正式结果还预留既有24小时接收时差，超出可证明的89天事件范围返回 `FACT_RETENTION_RANGE_NOT_COVERED`；观察计数不能当作完整长期比率。

新项目激活指标版本仍需完成现有运营设置、工作流和评分配置/review前置。遇到 `SCORE_CONFIGURATION_INCOMPLETE` 按现有配置入口补齐，不跳过门禁或仅凭少数叶子出分。`verify-r4c`生成的隔离历史项目已走过完整配置/review/激活，可用于查看版本历史与旧定义保持；没有改写既有项目active。
