## 保留数据部署

```bash
git fetch origin
git switch agent/v1-8-r5a-quality-collectors
git pull --ff-only
./scripts/dev up-preserve
./scripts/dev smoke
```

先读取R4-C Mac指引的Docker Desktop配置及账户说明。不要执行reset/down -v，不修改已激活版本。开发专项需要仓库声明的Node24/pnpm；基础Docker部署不要求宿主安装这些依赖。

## 验收顺序

1. 依业务接入指南在隔离项目安装quality扩展。未启用时不应包装fetch、不新增质量事件；重复createTracker返回原实例。
2. 完成真实业务首屏，测99/100/1000/1001行列表；同一完成函数多次调用只报一次。切换页面检查先leave后view，长请求归原页面。
3. 执行HTTP200成功、HTTP200业务拒绝、HTTP500、网络中断、宿主超时和取消。API总数包括全部受控尝试；业务拒绝不计技术失败。
4. 对受控资源执行一次成功及失败，核对分子1/分母2；不接入资源适配器时不能显示完整资源错误率。
5. 非空根页面、空根页面分别停留3秒；提前离开/隐藏不应当成检测正常。确认规则版本和启用PV分母。
6. 触发受控JS异常，确认只附安全类型/首帧/50条以内语义breadcrumb；不出现token、query、正文、DOM/表单值。大量同指纹错误需要披露抑制及不可用。
7. 查询quality API检查observedValue与正式value区别、sample、覆盖、P50/P75/P90/P99。当前窗口未闭合应null和明确原因；不能期待立刻得到正式质量分。
8. 新建质量草稿并刷新quality-facts，查看diff/lineage后按既有流程评审；旧active与历史结果保持。不要修改默认权重。
9. 使用Chromium/WebKit重复关键流程，unsupported指标不能伪造0；回归R1–R4-C常用管理、业务分析及组织声明。
