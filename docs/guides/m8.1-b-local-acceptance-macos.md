# M8.1-B / P1 Mac 本地验收

## 1. 静态与单元验收

```bash
pnpm install --frozen-lockfile
pnpm check
node tools/m8-p1-payload-report.mjs
```

预期：schema 只接受 v3；SDK 版本为 0.4.0；contract、SDK、API、读模型与 UI 测试通过；payload 报告不超过单事件 8 KiB / 批 64 KiB。

## 2. 干净环境数据流

仅对明确的本地测试资源执行：

```bash
./scripts/dev reset --confirm-local-data-loss
./scripts/dev bootstrap
./scripts/dev up
./scripts/dev smoke
```

确认 MySQL 包含 `project_collector_settings`，ClickHouse `raw_events` 包含 P1 汇总列；重复 migration 不报错。

## 3. 产品主流程

1. 登录后先到入口页，确认能看到所有授权项目；点击一个项目先进入项目概览。
2. 进入“设置 → 采集开关”，确认七类 collector 均可独立开关/采样；viewer 只读，admin/owner 可“保存为新版本”。
3. 发布全关版本，重新加载宿主并确认基础 page/feature 仍产生，P1 不产生。
4. 对 demo 发布启用版本；进入 demo 的“错误与性能”，依次触发 API、资源、首屏 readiness、列表渲染、JS 错误，再切换路由使 pageView 结算。
5. 进入“页面分析”，确认显示 API 分母/P50/P90/成功错误慢率、资源分母/失败率、首屏与列表、长任务影响 PV 率、白屏候选和 coverage/采样率。
6. 选择没有启用 P1 的时间范围或项目，确认显示“未采集”而不是 0；小于 20 个时长样本时 P90 为“—”且状态为“样本不足”。

## 4. 隐私与宿主隔离

- 请求 URL 加 query/token、动态数字 ID；结果只出现归一化 path。
- 未在 allowlist 的 action key 不进入 breadcrumb；breadcrumb 只在错误事件上出现且不超过 50 条。
- Canvas/Cesium/骨架页面未接 readiness adapter 时不能显示白屏率。
- `api.globalFetch=false` 时 `window.fetch` 身份不变；启用后 destroy 恢复，且 collector 请求不递归。
- 浏览器 payload、ClickHouse、日志与死信中不得出现 DOM、selector、输入、console、header/body、邮箱、token 或业务对象 ID。

## 5. 容量与回滚

```bash
bash scripts/m7 load full
```

按每个 collector 分别记录平均/峰值事件数、P50/P95 大小、批大小、Kafka lag、consumer throughput、ClickHouse 写入和查询扫描量。要求仍为 20 events/s 持续 60 秒、200 events/s 峰值 10 秒、接收无失败、p95 ≤1 秒且 120 秒内可查询。

回滚时由 admin 发布所有 `enabled=false` 的新版本；若宿主请求受影响，优先只关 `api.globalFetch`。确认基础 page/feature 数据不中断。
