# ADR-021：诊断原文与项目访问权限

- 日期：2026-10-10
- 状态：用户已决定诊断信息不脱敏；技术方案纳入开发计划，代码尚未实施
- 来源：Jesse 本次明确要求“不需要脱敏，只要是有价值的诊断信息都收集了。但是可以考虑展示时什么角色的用户能看到”
- 执行依据：[运行时诊断能力补齐计划](../planning/runtime-diagnostics-development-plan.md)

## 背景

R8 手工验收发现错误已入库，但原始消息不展示、SDK 首帧与 API 解析格式不一致、另一采集器把具体消息替换为固定字符串；没有 console 上下文。仅能统计错误，不能完成工程定位。2026-10-09 的时间窗口修复没有补齐这些能力。

## 决定

1. 本扩展的错误消息、堆栈、console、选定请求及上下文保留原文，不做内容脱敏，不以 `JavaScript exception` 或占位符代替具体诊断事实。
2. 采集限流、大小/序列化预算与保留期继续存在，并显式标记丢失/截断/不可访问原因；它们不等于内容脱敏。
3. 原文与聚类/指标使用的派生字段分开保存。规范 route、既有分母、错误率和评分不因原文扩展而改变；诊断采样不减少基础错误计数。
4. 展示权限在服务端实施，复用项目成员关系，新增诊断 read/export 能力；平台 admin 沿用管理权限，普通 viewer 默认只有统计摘要，获授权的项目成员可读原文。不通过隐藏按钮代替访问校验。
5. 详情、原文搜索、导出和 SourceMap 统一授权与审计；SDK 公共 appId 和旧外部 token 不获得原文读取权。运行日志/Prometheus 保存诊断元数据，不旁路复制原文。
6. SourceMap 与源码定位纳入 D5；浏览器能力限制、对象不可序列化、无栈和解析失败分别呈现。原始栈不能因解析失败丢弃。
7. 本次只授权计划提交。权限默认值、数据合同与容量初值按计划 D0 落实；D0–D7 未实施前不得宣布这些能力已交付。
