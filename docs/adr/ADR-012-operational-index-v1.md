# ADR-012：项目运营指数 v1

- 状态：Accepted
- 日期：2026-07-29
- 对应基线：requirements-v1.6、mvp-plan-v1.3

## 背景

Supervisor 需要项目级摘要，但单一分数可能掩盖数据缺口或把“停留更久、访问更深”误解为普遍更好。

## 决策

1. 指数名称为“项目运营指数”，不是综合健康度。
2. 一级维度及默认权重：
   - 使用覆盖 30%
   - 持续使用与访问深度 25%
   - 任务达成 30%
   - 使用效率 15%
3. 子权重固定使用 requirements-v1.6 第 9.3 节基线。
4. 评分方向只允许 `higher_better`、`lower_better`、`target_range` 和 `none`。
5. 目标、floor、ceiling、目标区间、minimum sample 与权重随 profile version 保存。
6. 激活 profile 不原地修改；编辑使用 clone-on-write 新版本和生效时间。
7. 总分仅在至少 3 个一级维度 eligible、叶子权重覆盖率至少 70%、数据状态可用且样本满足时显示。
8. 缺失值不按 0，数据质量不加业务分。
9. 响应必须包含原始值、目标、得分、贡献、样本、版本、eligible 与原因。
10. radar 只展示四个 0–100 维度，并提供完全等价的键盘可访问表格。
11. 使用效率中的页面时长分项以“逐页面模板符合度”的关键度加权结果作为原始比率，再按 `higher_better` 归一化；持续监测、信息分析、任务操作页面不会先汇总为同一个毫秒数。
12. profile、目标或实体配置在查询范围内生效时，只对所有相关配置均已生效后的交集范围求值，并明确返回部分可用边界；不会跨版本连接或混算总分。

## 后果

- 数据不足时总分为 null，但原始指标和已计算分项仍展示。
- 关键页面和任务只按显式权重聚合。
- 趋势默认只连接同一 profile/definition version。
- M8 错误/性能加入时发布指数 v2，不改写 v1。
