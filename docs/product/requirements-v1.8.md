## 0. 文档定位与事实优先级

v1.8 是一次面向当前 `main` 实现的产品重构，不是对 v1.7 的修订。发生冲突时按以下顺序处理：

1. 本文已经明确的产品决策；
2. 2026-08-18 附件中的业务目标和页面意图；
3. `main` 的真实代码、数据能力和安全边界；
4. v1.6/v1.3 中仍被本文保留的指标语义、权限、隐私和工程原则；
5. 其他历史文档仅用于追溯，不构成验收条件。

当前项目仍处于开发阶段，未正式上线，也没有需要保留的生产数据。因此本轮重构采用 **Pre-1.0 重置策略**：

- 可以清理测试数据、重建本地数据库和重新生成 seed；
- 可以删除被新信息架构替代的路由、接口、字段和兼容分支；
- 不为 v1/v2 历史测试数据设计回填、双写或数据迁移；
- 不保留 v1.7/v1.4 的产品兼容层；
- 已验证的数据链路、隐私保护、权限、指标计算和可观测性能力应复用，不因允许重置而无理由重写。

## 1. 本版决策摘要

1. 登录后先进入“全部项目”入口页，不再默认进入“功能采用”。
2. 产品由 6 个一级模块组成：入口页，以及项目内的项目概览、业务分析、页面分析、指标管理、设置。
3. 项目内页面统一采用“左侧项目导航 + 右侧正文”的框架；项目级公共时间筛选位于正文顶部。
4. 原“功能采用、运营概览、页面访问、项目运营指数、前端可观测性、项目与接入”不再作为并列一级导航，而是重组进新的 5 个项目模块。
5. “项目运营指数”在 UI 中改称“运营分数”，继续复用已经实现的可解释四维评分能力。
6. 新增“质量分数”。错误和性能不再只停留在独立证据页，而是通过独立版本、独立公式进入质量评分；不得改写运营分数的语义。
7. 指标管理成为所有分析页的单一配置和语义来源，统一管理分析对象、运营指标、质量指标、分数组合和版本库。
8. 指标面向用户分为“原子指标”和“业务指标”。内部仍可保留 fact/atomic/derived/composite 分层。
9. 用户可以基于受控指标和受控运算符创建业务指标与分数，但不能提交任意 SQL、任意字段、任意 group by 或任意代码。
10. 指标启用、停用或修改必须先形成新的草稿版本；激活后版本不可原地编辑，版本是当时指标配置的完整快照。
11. 业务分析以“业务域”为聚合单位。现有 module 能力升级并统一命名为 business domain。
12. 现有单次 operation 生命周期扩展为可选的多阶段工作流追踪；核心 SDK 继续使用显式语义事件，不默认抓取任意 DOM。
13. 页面分析默认打开“质量分析”，并可切换到“运营分析”。
14. 设置页包含接入指南、探针版本管理和接口管理；第三方接口默认关闭并使用独立的受限凭证。
15. 重构按页面或模块分批交付，每一批独立自动化验证、手工验收并合入后再开始下一批。

- 登录后没有项目资产入口页；

- 页面质量分析以错误组汇总为主，尚无附件要求的路径/时间/类别/复现条件筛选与明细；
- 项目与接入页尚未覆盖探针版本策略和第三方接口启停管理。

## 3. 产品定义

### 3.1 产品定位

Frontend Insight 是面向内部 Web 产品的前端监测平台。它通过用户行为、任务生命周期、浏览器错误和性能事实，为项目负责人、产品工程师和研发提供三类支撑：

1. **项目级判断**：项目在运行生命周期内的运营情况、前端质量和资产状态；
2. **业务级判断**：某个业务域、功能或工作流是否被使用、是否完成、耗时是否合理；
3. **页面级判断**：某个页面的运营指标、错误、性能和复现上下文。

平台提供证据、偏离信号和调查优先级，不仅凭遥测自动宣布设计“好/坏”，也不用于人员绩效评价。

### 3.2 目标用户

| 角色 | 核心任务 | 权限 |
| --- | --- | --- |
| 项目负责人/Supervisor | 快速判断项目运营和质量状态，下钻低分原因 | viewer |
| 产品/运营 | 查看业务域、页面、功能和工作流的使用与趋势 | viewer |
| 业务开发者 | 定位错误、性能问题和复现上下文，验证埋点 | viewer 或 admin |
| 项目管理员 | 管理项目、分析对象、指标、分数、探针和接口 | admin |
| 平台维护者 | 部署、链路健康、备份恢复和容量管理 | 运维权限 |

viewer 不能修改任何会影响指标、分数、采集或外部暴露范围的配置。所有 admin 修改必须写入审计日志。

### 3.3 设计原则

| 原则 | 要求 |
| --- | --- |
| 最多三层入口 | 全部项目 → 项目模块 → 详情抽屉/弹窗，不继续增加嵌套导航 |
| 项目先行 | 用户先选择项目，再进入项目分析；项目上下文始终可见 |
| 事实与判断分离 | 原始值、样本、数据状态、目标、公式和分数都可查看 |
| 运营与质量分离 | 两类指标、公式、版本和分数独立，页面可并列展示 |
| 单一语义来源 | 所有页面从同一指标定义/版本服务读取名称、公式、单位和状态 |
| 受控自定义 | 允许组合业务指标，不允许任意 SQL、任意代码或任意维度 |
| 版本不可变 | 激活版本不原地编辑，修改通过新草稿版本完成 |
| 数据状态优先 | 缺失、样本不足、延迟和 0 是不同状态 |
| 默认保护数据 | 不采集凭证、表单、DOM 文本、请求/响应正文和原始敏感标识 |
| 颜色有文字等价 | 绿色、黄色、红色符合常识，但颜色不能是唯一状态表达 |

## 4. 信息架构与公共框架

### 4.1 六模块信息架构

~~~mermaid
flowchart TD
    A["登录"] --> B["入口页：全部项目"]
    B --> C["进入项目"]
    C --> D["项目概览"]
    C --> E["业务分析"]
    C --> F["页面分析"]
    C --> G["指标管理"]
    C --> H["设置"]
    E --> I["工作流/指标详情"]
    F --> J["错误或页面详情抽屉"]
    G --> K["指标/版本编辑抽屉"]
~~~

推荐规范路由：

- `/projects`：全部项目；
- `/projects/:projectId/overview`：项目概览；
- `/projects/:projectId/business`：业务分析；
- `/projects/:projectId/pages?tab=quality`：页面分析；
- `/projects/:projectId/metrics`：指标管理；
- `/projects/:projectId/settings`：设置。

详情优先使用抽屉或弹窗，避免形成第四层入口。URL 必须保留项目、时间范围、TAB 和业务域/页面筛选，刷新和分享后状态不丢失。

### 4.2 项目内页面框架

项目内页面采用左右结构：

- 左上：项目名称、返回“全部项目”；
- 左下：项目概览、业务分析、页面分析、指标管理、设置；
- 右上：公共时间筛选、项目时区、账号和退出；
- 右下：当前模块正文。

公共时间预设：

| 预设 | 查询粒度 | 趋势横轴 |
| --- | --- | --- |
| 最近 7 天 | day | 日 |
| 最近 30 天 | day | 日 |
| 最近 3 个月 | week | 周 |
| 最近半年 | month | 月 |
| 最近 1 年 | month | 月 |

默认最近 7 天。页面分析可以切换为自定义开始/结束时间；自定义范围仍受最大 13 个月限制。所有范围使用项目时区。

### 4.3 公共数据状态

| 状态 | 展示 |
| --- | --- |
| healthy | 链路正常、显示最近更新时间 |
| delayed | 保留最近可用数据，显示延迟范围和刷新入口 |
| no_data | 区分首次未接入与所选范围正常无访问 |
| broken | 显示链路告警、request ID 和排查入口 |
| partial | 标出缺失时间段，趋势线不跨缺口连接 |
| insufficient_sample | 显示原始值和样本，不生成分数 |
| missing_configuration | 显示配置入口，不使用隐式默认冒充分数 |
| forbidden | 说明无项目权限，不泄露项目数据 |

## 5. 入口页：全部项目

### 5.1 目标

入口页展示已接入项目资产，使用户无需先选择下拉框即可回答：

- 当前有多少项目；
- 哪些项目运营或质量需要优先关注；
- 哪些项目链路不可达、数据过期或仍待配置；
- 最近一次数据更新时间是什么。

### 5.2 页面结构

页面为上中下三层：

1. 顶部：项目名称模糊搜索、新建项目；
2. 中部：项目卡片；
3. 底部：分页。

新建项目仅 admin 可见。弹窗至少配置项目名称、时区、允许 Origin、数据保留时间和初始指标模板；创建成功后刷新列表并定位新项目。

### 5.3 项目卡片

每张卡片显示：

- 项目名称；
- 运营分数；
- 质量分数；
- 项目状态；
- 链路状态；
- 最近数据更新时间；
- 缺少配置或样本时的原因；
- “进入项目”主操作。

分数不可用时显示“—”和原因，不能按 0 处理。

### 5.4 项目状态与颜色

附件正文的 80 分状态门槛和线框图的 85/60 颜色分段含义不同，v1.8 明确分开：

- **项目状态**：链路 healthy 且运营分数、质量分数均可用并高于 80 时为“正常”；链路 delayed/broken、任一分数不高于 80 时为“告警”；缺少配置或样本时为“待配置/数据不足”，不伪装成告警或正常。
- **分数颜色**：≥85 为绿色，60–<85 为黄色，<60 为红色，不可用为灰色。

颜色旁必须同时显示文字标签和触发原因。

### 5.5 列表行为

- 项目名模糊搜索，300 ms 防抖；
- 默认按“告警优先、最近更新倒序”；
- 支持 12/24/48 每页；
- viewer 只看到已授权项目；
- 无结果时保留搜索条件并提供清空入口；
- 卡片汇总接口不得为每张卡片产生独立 N+1 查询。

## 6. 项目概览

### 6.1 目标

用户进入项目后第一眼能够判断：

- 采集链路是否正常；
- 项目运营分数与质量分数；
- 哪个分数维度拖累总分；
- 主要运营指标当前值和变化趋势；
- 是否存在需要关注的固定告警。

### 6.2 页面组成

1. 链路状态、最近更新时间和“刷新数据”；
2. “项目运行情况”：运营雷达 + 运营分数、质量雷达 + 质量分数；
3. “运营指标”：当前激活版本中被标记为概览展示的指标卡；每张卡显示名称、值、单位、数据时间、业务描述和状态，超出一屏时使用可访问的美观滚动容器；
4. “指标变化趋势”：多选指标趋势；
5. “告警摘要”：P1，可配置展示；P0 复用现有固定告警。

### 6.3 运营分数

运营分数继承当前项目运营指数的解释性和门槛：

- 默认四维：使用覆盖 30%、持续使用与访问深度 25%、任务达成 30%、使用效率 15%；
- 可由分数管理创建新版本并调整维度、指标、目标和权重；
- 缺失值不按 0；
- 至少 3 个 eligible 维度且叶子权重覆盖达到配置门槛后才显示总分；
- 雷达图只展示 0–100 的维度分，不直接混入 PV、人数、毫秒等不同单位；
- 总分、维度、原始指标、目标、样本、版本和加权贡献可下钻。

v1.8 UI 使用“运营分数”，内部旧 `project_operational_index` 可在重构时统一重命名；不保留面向用户的双术语。

### 6.4 质量分数

质量分数是独立业务指标，默认由以下维度组成：

| 维度 | 默认输入 | 方向 |
| --- | --- | --- |
| JS 稳定性 | 每千 PV 的 JS 错误影响率 | lower_better |
| 资源稳定性 | 每千 PV 的资源加载错误影响率 | lower_better |
| API 稳定性 | 每千 PV 的 API 错误影响率 | lower_better |
| 页面性能 | Web Vitals poor 样本率及 p75 目标符合度 | lower_better/target_range |

默认公式等价于“100 分基线减去错误和性能扣分”，但实际扣分阈值、上限和权重来自激活的质量分数版本，不硬编码在页面。

质量分数要求：

- 错误率分母和 Web Vitals minimum sample 明确；
- 链路 broken/delayed 时不生成可信分数；
- 没有足够 PV 或性能样本时返回 unavailable/insufficient；
- 不使用“没有采到错误”自动推断质量满分；
- 与运营分数使用不同 metric set/version；
- 默认不把数据链路健康本身当作质量加分，只把它作为可计算 gate。

### 6.5 雷达与趋势配置

- 每个分数可从已激活分数定义中选择 3–6 个维度用于雷达；
- 修改展示维度不修改分数公式；修改公式必须创建新版本；
- 趋势指标与“运营指标”同源；
- 原始不同单位指标不使用堆叠折线图；
- 同单位最多 4 条非堆叠折线；混合单位使用小多图或先选择单位组；
- 周/月粒度遵循公共时间规则，缺口不补 0。

## 7. 业务分析

### 7.1 业务域

业务域是用户定义的稳定业务分组，例如能源管理、设备管理、报警管理。现有 module 数据模型在 v1.8 中重命名为 business domain：

- 每个页面属于一个业务域；
- 业务域由 admin 显式配置，不从 URL 自动推断；
- 可设置顺序、状态和关键度；
- 未归类页面继续显示基础数据，但不进入业务域聚合和分数。

### 7.2 页面结构

1. 筛选层：业务域单选、公共时间范围；
2. 业务运营指标：从当前运营指标版本选择的业务域指标卡；
3. 指标变化趋势：与指标卡同源；
4. 工作流追踪：展示所选业务域内关键工作流的开始、阶段达成、终态、耗时和异常。

默认指标至少包括业务域 PV、活跃账号/浏览器、页面覆盖、任务达成、产品稳定性和平均/分位操作耗时。只有单位和聚合语义兼容的页面指标才能汇总为业务域指标。

### 7.3 工作流定义

一个工作流由有序阶段组成：

| 字段 | 说明 |
| --- | --- |
| workflowKey/name | 稳定标识与业务名称 |
| businessDomainId | 所属业务域 |
| startPolicy | 如何创建匿名 workflow instance |
| steps | 2–20 个有序步骤 |
| terminalPolicy | 成功、失败、取消、超时 |
| timeoutSeconds | 整体超时 |
| version/status | 草稿、激活、停用 |

步骤触发类型：

- 显式 SDK action；
- 稳定 `data-fi-action`/ID 选择器适配器；
- 受控网络请求完成；
- 页面生命周期，如加载完成或刷新；
- operation 成功/失败/取消。

普通 class 容易随样式变化，UI 可以录入但必须提示不稳定；推荐使用显式 SDK step key 或 `data-fi-action`。平台不默认扫描全部点击，不采集 DOM 文本。

### 7.4 工作流事件流程

~~~mermaid
flowchart LR
    A["开始触发"] --> B["生成匿名 workflowInstanceId"]
    B --> C["步骤 1 达成"]
    C --> D["步骤 2…N 达成"]
    D --> E{"终态"}
    E -->|成功| F["completed"]
    E -->|失败| G["failed"]
    E -->|用户取消| H["canceled"]
    E -->|超时无终态| I["approximate_abandoned"]
~~~

每个事件携带 workflow instance、definition version 和 step key。同一工作流并发实例不能串联；业务 ID、设备 ID、报警 ID、人员 ID 不得作为 instance ID。

### 7.5 工作流指标

- started instances；
- 各阶段到达率和阶段流失；
- completed/failed/canceled/approximate abandoned；
- 总耗时 p50/p75；
- 相邻阶段耗时 p50/p75；
- 完成前页面数和业务域跨度；
- 指标可用起始时间和定义版本。

点击按钮只表示步骤发生，不自动代表业务成功。网络请求成功也只有在工作流定义明确时才可作为终态。

## 8. 页面分析

页面是分析系统中的最小产品单元。页面分析包含“质量分析”和“运营分析”两个 TAB，默认质量分析。

### 8.1 公共筛选

- 路径：单选、支持模糊匹配，默认 ALL；
- 开始/结束时间：默认最近 7 天；
- 筛选写入 URL；
- 仅返回当前项目已授权数据；
- 路径使用归一化 route，不暴露 query/hash。

### 8.2 质量分析

额外筛选“错误类别”：

- ALL；
- API/Ajax；
- resource；
- Vue；
- React；
- Promise；
- JS；
- other。

核心 SDK 保持框架无关。Vue/React 类别由可选适配器或显式安全字段产生，不能依靠上传源码或 DOM 猜测。

错误明细表至少包含：

| 列 | 要求 |
| --- | --- |
| 路径 | 归一化 route |
| 时间 | 项目时区，精确到秒 |
| 堆栈信息 | 脱敏且截断的首帧/有限帧 |
| 复现条件 | 结构化安全上下文，点击打开抽屉 |
| 类别 | 标准化错误类别 |

为控制高频错误量，列表支持 error group 折叠、游标分页和“只看最新一次/查看全部实例”。默认保留现有稳定 error group 能力。

“复现条件”只能包含：

- 页面 route、release、environment；
- 浏览器/OS 家族和视口档位；
- navigation/lifecycle 类型；
- API 方法、脱敏路径和状态码；
- 已显式追踪的最近工作流 step key；
- SDK/schema 版本。

禁止包含 Authorization、cookie、header、query、请求/响应正文、表单、DOM 文本、账号原值、设备/报警/人员标识和录屏。

### 8.3 运营分析

1. 页面运营指标卡：从指标管理中选择的页面级运营指标；
2. 指标趋势：与卡片同源；
3. 页面模板、所属业务域、核心状态和可用起始时间；
4. 页面内关键工作流/任务；
5. 未归类页面的 admin 配置入口。

默认保留 PV、活跃账号/浏览器/会话、平均/p50/p75 可见时长、时长覆盖率、访问深度和关键任务达成。缺失 leave 不按 0 参与时长。

## 9. 指标管理

### 9.1 定位

指标管理是平台的配置与语义中心。入口页、项目概览、业务分析和页面分析不得维护各自独立的公式或指标名称。

页面包含：

1. 分析对象：业务域、页面、工作流；
2. 运营指标；
3. 质量指标；
4. 分数管理；
5. 版本库。

### 9.2 用户术语与内部层级

| UI 术语 | 内部实现 | 示例 |
| --- | --- | --- |
| 原子指标 | fact/atomic 固定查询 | PV、错误次数、Web Vital p75 |
| 业务指标 | derived/composite DAG | 任务达成率、每千 PV 错误率 |
| 分数 | 0–100 composite | 运营分数、质量分数 |

系统默认原子指标由代码和固定查询提供。用户不能修改其底层 SQL，但可以在新版本中启用、停用、调整展示和引用。

### 9.3 受控业务指标公式

用户定义业务指标必须基于已注册指标，不直接基于任意列或原始事件。

允许的首版运算：

- `+`、`-`、`*`、`/`；
- `min`、`max`、`clamp`；
- `weighted_mean`；
- `normalize(higher_better/lower_better/target_range)`。

约束：

- 公式保存为经过校验的 AST，不保存可执行代码；
- 最多 20 个输入、8 层深度、100 个节点；
- 加减必须单位兼容；
- 乘除必须经过单位规则校验；
- 除数为 0 返回 metric_not_available，不隐式返回 0；
- 缺失值默认传播，不允许用 `coalesce(..., 0)` 掩盖数据缺口；
- 输入 entity scope 和时间粒度必须兼容；
- DAG 不能循环；
- 每个指标声明名称、业务问题、单位、分母、去重键、missing policy、minimum sample、owner 和版本；
- 服务端计算，前端不得独立实现另一套公式。

### 9.4 分数管理

分数是一类返回 0–100 的业务指标，包含：

- 分数 key、名称、类型（运营/质量）；
- 3–6 个维度；
- 每个维度的指标、目标、方向和权重；
- 总分展示 gate；
- 颜色分段；
- 雷达展示维度；
- 适用项目/业务域；
- definition version 和 metric set version。

权重总和必须为 100%。未达到 minimum sample、缺少目标或数据延迟的分项不按 0；总分是否可显示由覆盖门槛决定。

分数内部统一保存 0–100 数值，展示单位可以选择“分”或“%”；切换展示单位不能改变公式、阈值或底层数值。

### 9.5 版本库

指标版本是完整快照，包含分析对象引用、指标定义、公式、启停、展示位置、分数定义和依赖版本。

~~~mermaid
stateDiagram-v2
    [*] --> Draft: 新建/复制版本
    Draft --> Validating: 保存并校验
    Validating --> Draft: 校验失败
    Validating --> Active: admin 激活
    Active --> Superseded: 激活后续版本
    Superseded --> Active: 重新激活旧快照
    Draft --> Abandoned: 放弃草稿
~~~

规则：

- 激活版本不可原地修改；
- 修改已激活指标时自动复制出新草稿；
- 激活前展示依赖、受影响页面、公式 diff 和测试结果；
- 同一项目、同一类型同一时刻只有一个 active version；
- 重新激活旧版本是选择旧快照，不是修改历史；
- 开发阶段可以清理测试数据，但版本不可变仍是产品能力，不能省略。

### 9.6 指标血缘

所有业务指标和分数必须能从结果沿 DAG 下钻到原子指标。血缘抽屉展示：

- 当前公式和版本；
- 直接上游与下游；
- 单位、样本和缺失规则；
- 被哪些页面、卡片、趋势和分数引用；
- 循环或失效依赖的校验结果。

## 10. 设置

### 10.1 接入指南

- 展示项目 key、接收 endpoint、允许 Origin 和 CSP；
- 按当前探针版本生成最小接入代码；
- 支持发送测试事件和查看链路状态；
- 明确 SDK 不读取 Authorization、Cookie、Local/Session Storage token、表单、DOM 文本和 URL query；
- 将项目基础配置、成员与 Origin 管理收拢到设置。

### 10.2 探针版本管理

页面显示：

- 当前推荐版本；
- 项目最近观测版本及占比；
- supported/deprecated/blocked 状态；
- release notes 和升级建议；
- 事件契约版本；
- 最后观测时间。

平台不远程修改业务项目依赖，也不自动升级探针。blocked 只表示服务端拒绝策略已明确并经过管理员配置。

### 10.3 接口管理

接口管理用于向 Prometheus 或获准的第三方系统暴露稳定读模型。

首版接口类型：

- 当前指标快照；
- 指标趋势；
- 错误组/质量摘要；
- Prometheus scrape。

表格列：

- 接口；
- 描述；
- 参数（悬浮 tooltip）；
- 状态；
- 最近调用；
- 启用/停用。

支持分页。接口默认关闭；启用时创建独立、可撤销、按项目/接口/范围授权的访问凭证，数据库只保存 hash。`projectKey` 不是接口凭证。

所有外部接口必须：

- 固定字段和时间范围；
- 限流、审计、request ID；
- 不接受任意 SQL、公式、字段或 group by；
- 不暴露错误原始敏感内容；
- 禁用后立即拒绝新请求；
- Prometheus 标签禁止使用 route、error message、account 等高基数字段。

## 11. 指标、分数与页面的数据流

~~~mermaid
flowchart LR
    A["浏览器事实事件"] --> B["ClickHouse 去重事实"]
    C["项目/分析对象配置"] --> D["原子指标固定查询"]
    B --> D
    D --> E["业务指标 DAG"]
    F["激活的指标版本"] --> E
    E --> G["运营/质量分数"]
    G --> H["入口页与项目概览"]
    E --> I["业务分析"]
    E --> J["页面分析"]
    K["MySQL 版本/公式/审计"] --> F
~~~

### 11.1 统一计算前提

- 按 eventId 去重；
- 使用项目时区和归一化 route；
- 账号、浏览器、会话口径分开；
- 0、null、insufficient、missing_target、delayed 分开；
- 原子指标使用固定查询；
- 业务指标使用纯函数/DAG 求值；
- 趋势逐时间桶计算同一公式，不能先求总值再平均；
- 指标名称、公式说明和单位由服务端目录返回；
- 计算结果携带 definition version、metric set version、sample size、availableFrom 和 data status。

## 13. 隐私、安全与权限

### 13.1 继续禁止采集

- Authorization、Bearer token、cookie；
- Local/Session Storage 内容；
- URL query/hash 和完整 referrer query；
- 请求/响应 header 与正文；
- 表单、DOM 文本、键盘、剪贴板、截图和录屏；
- 姓名、手机号、邮箱、身份证；
- 设备、报警、人员等业务 ID 作为 operation/workflow instance ID；
- 任意未声明嵌套对象。

### 13.2 错误与工作流新增边界

- 堆栈只保存脱敏有限帧；
- 动态路径 ID 在浏览器侧归一化；
- framework category 不能上传源码；
- 最近工作流上下文只包含 step key，不包含业务值；
- DOM 选择器只作为配置元数据，不保存命中的 DOM 文本；
- API export token 不返回第二次，支持轮换和撤销；
- 日志、死信和审计不记录事件 payload 或接口 token。

## 14. 非功能要求

| 项目 | 目标 |
| --- | ---: |
| 接收接口 p95 | ≤100 ms，仅校验与入队 |
| 数据可见延迟 p95 | ≤5 分钟 |
| 项目列表首次可用 p95 | ≤2 秒，20 个项目默认容量 |
| 核心 Dashboard 查询 p95 | ≤2 秒 |
| 最大查询范围 | 13 个月 |
| 单事件/单批 | ≤8 KiB / ≤64 KiB |
| SDK 同步处理 p95 | ≤2 ms |
| 可访问性 | 颜色有文字等价；图表有表格或文本摘要；键盘可操作 |

默认容量仍为不超过 20 个项目、日事件量不超过 100 万、平均 20 events/s、峰值 200 events/s。只有真实性能证据触发物化聚合或新存储组件。

## 15. 分模块验收标准

### 15.1 入口页

- [ ] 登录后默认进入全部项目；
- [ ] 项目模糊搜索、创建、分页和授权过滤正确；
- [ ] 卡片显示运营/质量分数、状态、更新时间和不可用原因；
- [ ] 链路异常和分数不足不会被误显示为正常；
- [ ] 项目汇总无 N+1 查询。

### 15.2 项目概览

- [ ] 运营与质量分数使用独立版本；
- [ ] 雷达维度、总分、明细表和贡献一致；
- [ ] 分数不可用时保留原始指标；
- [ ] 运营指标和趋势来自同一激活版本；
- [ ] 混合单位不使用误导性的堆叠图；
- [ ] 刷新和公共时间筛选生效。

### 15.3 业务分析

- [ ] 业务域聚合不包含未归类页面；
- [ ] 指标卡和趋势同源；
- [ ] 并发 workflow instance 不串联；
- [ ] 每阶段、终态和耗时与固定 fixture 手算一致；
- [ ] class/ID 适配器不采集 DOM 文本；
- [ ] viewer 无法修改工作流定义。

### 15.4 页面分析

- [ ] 默认进入质量 TAB；
- [ ] 路径、时间、错误类别筛选和 URL 状态正确；
- [ ] 错误明细包含规定列并可打开安全复现上下文；
- [ ] query/header/body/账号原值不出现在 UI、API、日志或死信；
- [ ] 运营 TAB 的指标与趋势来自指标管理；
- [ ] 未归类 route 显示配置入口但不进入评分。

### 15.5 指标管理

- [ ] 原子指标不能被任意 SQL 覆盖；
- [ ] 业务指标公式通过单位、scope、节点数、除零和循环校验；
- [ ] UI、API、趋势和分数使用同一公式；
- [ ] 激活版本不可原地修改；
- [ ] 修改先创建新草稿，激活前可查看 diff 和影响范围；
- [ ] 旧快照可重新激活；
- [ ] 血缘能追溯到原子指标；
- [ ] admin 写、viewer 只读、操作有审计。

### 15.6 设置

- [ ] 接入代码与当前项目/推荐探针版本一致；
- [ ] 测试事件能验证完整链路；
- [ ] 探针版本占比和最后观测时间正确；
- [ ] 外部接口默认关闭；
- [ ] token 只显示一次、数据库仅存 hash；
- [ ] 启停、轮换、限流和审计通过；
- [ ] Prometheus 无高基数/敏感标签。

## 16. 明确不在本轮

- 任意 SQL、任意 group by 和自助 BI；
- 用户上传或执行代码；
- 自动 DOM 录屏和行为回放；
- 请求/响应正文采集；
- SourceMap 上传与源码映射；
- 任意告警 DSL、通知编排和自动修复；
- AI 分析助手、多模型和对话历史；
- 个人级运营评分或员工监控；
- 外部多租户 SaaS；
- 为历史测试数据设计兼容、回填或双写。

AI 分析助手仍可在本轮数据与页面稳定后单独评审，不能与核心重构捆绑。
