## 指标口径与迁移

本次要求的页面身份规则，**仅针对 R6 页面使用指标**替代九月版本中仅统计已识别身份/已归类数据的业务过滤规则：统计 `page_view` 事件，传输重试按 `eventId` 幂等去重；UV 使用带命名空间的 `userId`，匿名时以 `deviceId` 兜底。分别披露匿名与已识别构成；不因登录行为推断或拼接前后身份。新定义 `page-usage-2026-10-06.1` 仅由新草稿采用；active 和历史快照绝不改写。历史身份定义继续有效，页面指标拒绝通过重命名其事实来冒充新口径。现有业务和评分定义保留各自的版本化范围。

沿用 ADR-019 时间窗口语义：先选择 `[from,to)` 内的事实，再按原始 `sessionId` 聚合；在选取页面样本前纳入范围内所有 route。跨午夜不拆分会话。空闲时间恰好达到 30 分钟时，下一次活动开启新会话；结算事件仍归属原会话。不能因仅筛选一个页面而制造跳出。单页会话率仅作诊断，不自动告警。

时长采用匹配同一 pageView、session 和身份的可见分段之和，并按事件 ID 去重。SDK r6-1 的页面浏览和离开事件携带受控的使用事实版本；离开事件携带单调递增的 `usageSequence` 和 `usageClosed`。只有序号连续且以终结结算结束的分段才是有效样本；仅有隐藏状态、中间分段缺失和旧版结算均不可用。抑制重复终结回调。缺失离开事实的样本不进入分位数计算，单独计数，绝不补零。选定页面浏览中只要有一个缺少有效时长样本，平均时长即不可用；已观测分段的覆盖率不能证明未上报流量的完整性。

DAU/WAU/MAU 分别按项目本地自然日、以周一为起点的自然周、自然月去重，并取与选定范围的交集。多个自然周期以序列展示，不求和或取平均后冒充单值。按小时分布将 DST 重复出现的本地小时合并，并对身份去重。空观测桶表示未知，不是零；真实的零时长或零跳出率予以保留。日历和小时序列明确属于观测诊断；指标卡和趋势使用同一版本绑定及求值器。

页面展示绑定复用现有版本化绑定表及 `project-pages/page` 展示范围。修改须经过草稿和既有审阅/激活流程。新增 DTO 和接口接替旧 `PagesView` / `PageDetailView` 的运营能力，不向旧 DTO 双写。缺少绑定时使用文档约定的默认使用指标集；已配置的绑定优先。

## 查询边界

使用一次有预算限制的 ClickHouse 查询，跨 route 读取去重后的页面事实：最多返回 50,000 个事件、扫描 1,000,000 行、执行 5 秒。超出预算时报错，不将截断结果当作成功。这是有预算限制的诊断实现，不构成生产容量承诺。工作流事实复用现有 R4-B 聚合器，查询成本单独计算，并通过页面绑定任务的操作 key 关联相应版本定义。定义元数据复用现有 MySQL 修订表和版本表。
