## 采用既有依据的实现边界

- ADR-017 首个终态：按事件时间排序；相同时间的矛盾终态没有可证明先后，标 unresolved。收到时间只限制 asOf 可见性，不用作业务胜出规则。
- 开始 cohort 为 `[from,to)`；终态读取至查询 asOf，同时要求事件时间和接收时间不晚于 asOf。跨窗口实例仍归开始 cohort。进行中仍在 started 分母；未解析样本使成功率不可用。
- timeout 在 `asOf >= startedAt + timeoutSeconds` 推导 approximate_abandoned，不写入浏览器终态。迟到真实终态按原事件时间重放，可替代先前近似观察；结果明确 provisional。
- 普通 task_duration 和阶段耗时使用既有线性插值算法，输出 P50/P90/P75/P99；评分仍使用批准的任务类型权重和池化加权 nearest-rank P50。
- 运行配置只返回安全定义和已登记 operationKey，Origin/项目/env受控，无管理凭证、no-store。SDK 0.5.0；每次安装使用取回的版本集合，实例开始后固定版本。
- SDK 的 network wrapper 必须显式提供业务成功谓词，HTTP200 本身不会达成步骤；原响应和异常返回宿主，不读取或上报正文。page lifecycle 仅监听调用方显式提供的 EventTarget 上的 `fi:page-loaded/refreshed`，不读取 detail。
- SDK sessionStorage 仅保存自己的随机 session/instance、定义 key/version、到达步骤与时间；不能传入业务实例ID。TTL/会话过期清理；销毁清理监听器。旧定义 canStart=false 只供未过期在途恢复。
- 004 迁移保留现有对象和事实，新增 workflow_admission_periods。升级前启停历史不能从当前状态推断，只从迁移时刻记录可证明准入；不回填伪历史。
- 生产 workflow 评分输入已读取真实实例，但覆盖证据未知时保持 partial；未改总分门槛，未使用 fixture 作为生产数据源。
