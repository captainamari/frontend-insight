## 性能与查询预算

使用同一 GitHub Actions 运行器：Linux x64、4 CPU、16,766,414,848 字节内存。R6 每个浏览器的 fixture 包含 9 次页面浏览，其中选定页面浏览 6 次、身份 2 个、选定会话 6 个，返回 18 条浏览/离开事实。已通过真实存储验证跳出率为 0.5、使用时长之和 / UV 为 4,500 ms。p95 采用最近秩法（nearest rank）。

| 检查项             | 预热次数 / 测量样本数 | HTTP p95 | ClickHouse 查询数              | 扫描行数 / 字节数 |
| ------------------ | --------------------- | -------- | ------------------------------ | ----------------- |
| R6 Chromium        | 5 / 20                | 38.94 ms | 3（使用指标 1 + 关联工作流 2） | 1,089 / 215,515   |
| R6 WebKit          | 5 / 20                | 43.92 ms | 3（使用指标 1 + 关联工作流 2） | 792 / 20,327      |
| R5-A 质量查询      | 3 / 20                | 44.67 ms | 1                              | 3,585 / 1,676,895 |
| R5-B Chromium 查询 | 5 / 20                | 22.50 ms | 1                              | 300 / 126,036     |
| R5-B WebKit 查询   | 5 / 20                | 21.91 ms | 1                              | 339 / 24,404      |

R6 元数据 SELECT 查询上限为 12 次，不含共用的身份认证检查。使用指标读取预算保持为：最多返回 50,000 个事件、扫描 1,000,000 行、执行 5 秒；超出预算明确报错。上表扫描数据来自单次请求的实际计数，可能随后台数据合并状态变化。

R5-A 压力检查全部接收 3,200 个事件：先以 20 EPS 持续 60 秒（1,200 个事件），再以 200 EPS 持续 10 秒（2,000 个事件），包含 640 条 API 事实和 1,280 条资源事实。采集请求 p95 为 105.85 ms，共 100 个 HTTP 批次，采集侧未预热；质量查询 p95 为 44.67 ms。这些是小规模 CI 样本和短时压力场景，**不构成生产容量保证**。

## 交接与剩余边界

请参阅 [R6 接入与验收指南](../guides/v1.8-r6-acceptance.md)和[决策记录](v1.8-r6-decisions.md)。已有工作草稿可显式刷新页面使用指标定义，并使原审阅失效；active 版本和历史快照保持不可变。不得将历史版本重新命名为 R6 使用指标。完整时长依赖当前 SDK r6-1 的终结分段事实；旧版、缺失、仅有隐藏状态或中断的结算仍标为不可用，并提供覆盖率诊断。

页面指标基于选定窗口内实际观测到的页面浏览样本。匿名身份与已识别身份不拼接。自然周期序列取与选定范围的交集；空观测桶表示未知，而非已确认的零值。不能从观测覆盖率推导出完整流量保证。本次有预算限制的诊断读模型不包含大范围预聚合和生产规模负载认证。
