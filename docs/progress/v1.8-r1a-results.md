## 2. 路由和 UI

- 新增正式路由：`/projects/:projectId/metrics?tab=analysis-objects`；
- 左侧导航新增“指标管理”；
- 分析对象内含“功能模块、页面、工作流”三个 TAB；
- R1-B/R1-C TAB 只显示禁用占位和里程碑，不返回虚假数据；
- 旧 `/operational-config` 暂时保留运营目标/profile，但功能模块与页面改为只读并链接到正式入口；
- 页面详情和运营概览的未归类入口改指向指标管理。

## 3. API

保留并收敛：

- `GET/POST/PATCH/DELETE /api/projects/:projectId/modules...`；
- `GET/POST/PATCH/DELETE /api/projects/:projectId/page-definitions...`。

新增：

- `GET/POST /api/projects/:projectId/workflow-definitions`；
- `PATCH/DELETE /api/projects/:projectId/workflow-definitions/:workflowId`；
- `PUT /api/projects/:projectId/workflow-definitions/:workflowId/draft`；
- `POST /api/projects/:projectId/workflow-definitions/:workflowId/activate`。

## 4. 数据、fixture 与版本变化

- 空库 baseline 为 `workflow_definitions` 增加 `module_id/status/disabled_at/updated_at`；
- workflow version 保存受控 `start_policy/terminal_policy/timeout/status`；
- workflow step 对顺序和 trigger kind 增加数据库约束；
- R0 seed 工作流补齐功能模块、终态策略与受控 SDK action 配置；
- 未新增历史迁移、别名、双写或生产数据回填；
- 本阶段没有 metric key、单位、公式、MetricCatalog 或 canonical manifest 变化。

## 5. 权限、审计和隐私

- viewer 写 API 在进入 store 前返回 403；
- 页面和工作流引用模块时按 `projectId + moduleId` 校验，禁止跨项目引用；
- workflow definition、draft、activate、disable 均按项目解析；
- 审计只保存 entity、版本、步骤数量和 changed fields，不保存 selector、网络路径、trigger config 或任意 DOM/表单值；
- 普通 class 可兼容录入但 UI 明示脆弱，优先推荐 SDK/ID/`data-fi-action`。
