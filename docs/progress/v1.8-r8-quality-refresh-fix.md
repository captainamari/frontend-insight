# R8 手工验收反馈：场景错误在质量分析中不可见

2026-10-09，用户确认已执行 R8 手工验收，反馈场景实验室触发 JS 错误后，切换环境仍看不到数据。这是“已执行、发现缺陷”，不能继续写为未执行，也不等于无问题通过。

## 原因与复现

截图的最近 7 天结束时间为 2026-10-08 15:44:34.231，查询快照已到 16:04:49。项目入口把预设范围解析为固定 from/to 并写入 URL。质量分析刷新只重查这个旧范围、更新接收快照，没有推进事件时间的结束边界。因此打开页面后触发的错误被 timestamp < to 排除，切换环境也继续使用相同时间段。

本地 Chromium 回归在旧代码上复现：刷新后请求的 to 仍为旧值；修复后所有预设范围均推进到当前时间。错误事件采集与服务端查询没有 qualityVersion 必须存在的限制，不能据此把旧实验室事件判为不可查询。

实验室发送环境实际固定为 dev，说明却写 production。此次统一显示 SDK 实际 appId、dev 和 release，并提示使用对应项目、环境和刷新按钮。staging/prod 不应显示 dev 的事件，不改变环境隔离。

## 修复与验证范围

- 显式刷新预设范围时按项目时区重新解析起止时间，同步 URL，清理旧分页游标与派生评分边界；保留页面、类别、错误组和模式。
- 自定义范围不改变日期；重复点击刷新仍请求新快照。浏览器重载、前进后退和复制链接仍保留 URL 中的时间快照。
- UI 回归覆盖 7/30/90/180/365 天、自定义范围、游标清理、筛选保留和同一时刻连续刷新。该用例明确使用模拟传输，只证明 UI 请求边界。
- 真实链路回归从场景实验室按钮产生错误，核对 202 接收后再等待 ClickHouse/API 中的特定 occurrence，检查页面刷新显示、dev/staging/prod 隔离及历史自定义范围不被扩大。Chromium/WebKit 均纳入 R8 CI。

本地无 Docker；真实服务结果以本次远端 CI 为准。既有 745308d 的绿色结果只证明旧版本，不能替代本次修复验证。修复后的手工复验仍需用户确认；R6、R7 和生产环境批准状态不因本反馈自动改变。CI 结果将在 PR 交接记录中追加。
