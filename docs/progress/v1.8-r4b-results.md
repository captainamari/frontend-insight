## SDK、API 与存储契约

- `tracker.startWorkflow(workflowKey)` 返回随机实例 handle；`reachStep`、`complete/fail/cancel`、`workflow.startOperation(operationKey)`、`getActiveWorkflows(workflowKey)`。关联 operation 使用 `succeed/fail/cancel`；任意业务 payload 不获准上传。scoped selector、network 业务谓词、显式 lifecycle 适配器均需调用方启用。
- `POST /v1/events/workflow-config`：`appId/env` + Origin 校验，无管理凭证，no-store；返回固定版本集合和 operationKeys，`canStart=false` 的旧定义仅供当前未过期 session 恢复。
- 列表、详情、趋势复用 `GET /api/projects/:projectId/business`。原 `env/range/from/to/granularity/moduleId/versionId/metrics` 上增加 `workflowPage`（1–100）、`workflowVersion`、`workflowEvidencePage`（1–1000）。每页20个定义版本；实例证据每页50条；无逐实例/步骤请求。`workflowAnalysis` 内返回定义分段、开始cohort、终态、漏斗、普通分位数、日历趋势、asOf、覆盖、排除原因、安全证据及扫描诊断。
- `GET /api/projects/:projectId/workflow-definitions/:workflowId/versions/:versionId` 读取分析引用的版本；项目与对象归属在服务端检查。`POST .../metrics/versions/:versionId/workflow-facts` 只允许管理员更新运营草稿的5个本批系统定义，之后仍须review/activate。
- contract v3 沿用既有 workflow 字段和 ClickHouse 列，不建立第二套事件协议；拒绝v1/v2及旧alias。MySQL `004_r4b_workflow_admission.sql` 新增准入区间及索引，保留原定义/事件；迁移重复执行由既有校验和机制保护。定义与准入区间在同一repeatable-read快照读取，避免激活并发产生混合配置。
- 所有读模型按项目/env隔离；事实每批最多50,000事件、路径最多5,000受控session/50,000页面事件；超限明确失败而非截断计算。最长范围、日/周/月及DST继承公共时间工具；90天物理保留期仍限制真实覆盖。
