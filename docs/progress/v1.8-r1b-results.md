## 3. 公式安全结论

服务端不保存或执行表达式文本、SQL、JavaScript、任意字段、任意函数或任意 group by。持久化的 `formula_ast` 先经 exact-key parser；每个 node 出现多余字段即返回 `FORMULA_FIELD_NOT_ALLOWED`。

单位规则：

- `+/-/min/max/weighted_mean` 要求相同单位；
- `*` 只允许一侧 scalar；
- `/` 允许单位除 scalar、同单位得到 ratio，以及显式批准的 compound unit；
- `clamp` 边界只能是 literal；
- normalize 统一输出 score，并校验 target 顺序；
- 分母为 0 返回 `metric_not_available`；null、insufficient、delayed 不转成 0。

## 4. 三个固定手算 fixture

| fixture                | AST 摘要                  | 输入                               |                       人工手算 | evaluator |
| ---------------------- | ------------------------- | ---------------------------------- | -----------------------------: | --------: |
| `pages_per_visit`      | `views / session_count`   | 120、40                            |                 `120 / 40 = 3` |       `3` |
| `weighted_activity`    | `weighted_mean(A×3, B×2)` | 80、60                             |       `(80×3 + 60×2) / 5 = 72` |      `72` |
| `latency_target_score` | `normalize(lower_better)` | value 300、target 100、ceiling 500 | `100×(500-300)/(500-100) = 50` |      `50` |

同一 fixture 的总值与趋势桶调用同一个 `evaluateFormula`，没有前端或趋势专用公式副本。

## 6. 数据库与版本不变量

- project + library type + version 唯一；
- generated `active_slot` 唯一索引保证同项目同类型最多一个 active；
- snapshot 记录 source version、creator、activated/superseded/abandoned 时间；
- active/superseded 内容只能读取，编辑/删除创建下一草稿；
- 重激活旧版本只切换状态，不更新 definition 行；
- system origin 与 business origin 分离；系统 key 永久占用；
- test 数据不做 alias、双写、回填或历史兼容，空库 baseline 直接重建。
